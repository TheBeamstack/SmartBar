# v1.0.4_prep_plan.md — Finalize v1.0.3 + prepare the v1.0.4 (façonnage) build

> **Purpose.** Two bodies of enabling work must land before the v1.0.4 façonnage build is meaningful:
> **Part A — finish v1.0.3 to 100%** (its code is done + pushed, but its *acceptance* gates are open: owner
> visual passes, a11y, docs, and the engineer sign-offs), and **Part B — prepare v1.0.4** (owner decisions,
> severity verification, a test safety net around the under-tested web adapter, shape-data authoring, design
> spikes, fixture inventory, and the impl-plan seed). This file is that combined Phase 0. Each task carries
> **objective · why it's needed · steps · deliverable · done-when · owner/agent · depends-on**, and the file
> ends with a **combined go/no-go checklist** + a **what-blocks-what** map.
>
> **Accuracy note (2026-07-03 re-analysis).** This rebuild corrects one spec claim: in **H1**, a Ø-only override
> on a façonné group throws in `evalExpr` (`expr.ts:46/50` — `makeScope` does **not** default missing params to 0),
> so it is a real crash; and Ø/`length` changes **must** regenerate the shape (Ø drives `bendDeduction` + hook
> extension → `cutLength`), so the earlier "skip regen on Ø-only" idea was wrong — only `axialPos`/`removed`-only
> overrides are geometry-neutral. `v1.0.4_spec.md` H1.2 + H5.2 were edited to match. Everything else in the spec
> re-verified against the code and holds (H2 `L`-only-on-DROITE no-op; `provided_area` reads `layout.count`
> `validation/index.ts:139`; `placeBars` skips `removed` `place.ts:176`).

# What blocks what

- **Part A and Part B run in parallel.** Finalizing v1.0.3 does **not** block *coding* v1.0.4 (v1.0.3 code is
  pushed + green; v1.0.4 builds on it).
- **V3.4 (engineer sign-off) is long-lead → start now.** It gates *acceptance* of any printed compliance number
  (both v1.0.3 and v1.0.4) and feeds v1.0.4's `[ENGINEER-GATE]` items (H5 mixed-Ø As, H14 stagger). It does **not**
  block v1.0.4's non-gated coding.
- **V3.2 (a11y) before H6/H7** — the new independent-bar UI should meet the parity bar the audit sets.
- **The v1.0.4 build starts when Part B (P0.1–P0.7) is green**, regardless of V3.4's timeline.
