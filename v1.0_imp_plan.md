# RebarConfig v1.0 — Implementation Plan (7 phases)

**Companion to:** `v1.0-Spec.md` (revision **r3**, 2026-06-24).
**Audience:** an implementing agent starting a fresh session. Each phase is self-contained: objective, prerequisites, exact file targets, contracts to implement, tests, and a binary "Definition of Done". Read the *Global Context* section once, then execute phases **P0 → P6 in order** — every phase compiles and tests against the artifacts of the previous one.
**Status:** validated against `v1.0-Spec.md` r3 (see §V — Validation Matrix at the end). Phases map 1:1 onto the spec's §12 milestones M0–M6.

> **Golden rule of this project (spec §0.1):** the engine never hard-wires element→scheme combinations. Everything structural is **data** (JSON manifests + code-pack functions). "Add JSON, no engine change" must remain true after every phase. If a task tempts you to add an `if (elementType === …)` branch in `/packages/core`, stop — it belongs in a manifest or a registered generator.

## Global Context (read once)

### Product in one paragraph
RebarConfig is a **client-side rebar *detailing*** SPA (not a structural-analysis tool). The user supplies the required steel area `As,req` per zone (from external analysis), picks an element + a reinforcement scheme, parametrizes bars/ties, sees live 3D, gets BAEL/EC2/RPS buildability feedback, and exports **BBS + DXF + PDF**. No backend in v1.0 (IFC + accounts are v1.1).

### Stack (spec §11)
- **Frontend:** React 18 + TypeScript, **Vite**. State: **Zustand**. Styling: Tailwind (suggested).
- **3D:** Three.js + `@react-three/fiber` + `drei`. Instanced meshes; `TubeGeometry`/`CatmullRom`.
- **Expression eval:** `mathjs` (for archetype `len_expr`/`totalLengthExpr`, frozen scope — §5.2.1f).
- **Exports:** `@tarikjabiri/dxf` (or equivalent), `pdf-lib`/`jspdf`, in-house BBS.
- **Tests:** **Vitest** (+ `@testing-library/react` for UI). Golden-file tests for BBS/DXF.
- **Hosting:** static build, free tier (Cloudflare/GitHub/Netlify Pages). No server, no DB, no secrets.

### Monorepo layout (spec §11) — create in P0
```
/packages/core         # pure engine: types, solver, validation, validity layer, exporters (TS, NO DOM/React)
/packages/codepacks    # BAEL-FR/ , EC2/ (rules, shapes, schemes, supplements, conventions); seismic/RPS-2011.json
/apps/web              # React SPA (viewport, UI, project IO)
/apps/web/manifests    # elements/*.json  shapes/*.json  schemes/**  supplements/*.json
/tests                 # unit + golden-file + engineering reference cases
```
Use a workspace tool (pnpm/npm workspaces). `@rebarconfig/core` must have **zero** runtime deps on React/DOM (enforced by an ESLint `no-restricted-imports` rule + a CI check).

### Non-negotiable invariants (verify in every phase)
1. **Engine purity:** nothing in `/packages/core` imports React, `three`, `window`, or `document`. Geometry is plain number arrays; the viewport (in `/apps/web`) turns them into meshes.
2. **Determinism:** the solver is pure functions — same input → byte-identical output. No `Date.now()`, no `Math.random()`, no floating non-determinism beyond a documented tolerance.
3. **Performance budget (spec §2.2):** solve + validate + redraw < **16 ms** for a typical element on slider drag. Heavy elements use the normative degradation path (debounce re-solve, render centerline `LineSegments` not tubes mid-drag, defer full validation; full solve on drag-release). Correctness is **never** skipped on commit.
4. **SI internally:** engine stores mm, mm²; UI/IO converts at the boundary (geometry mm, area cm² / cm²/m, weight kg). Units shown on every field.
5. **Code-pack agnosticism:** archetypes/schemes/validator call `code.*` named functions (§7.11); selecting BAEL vs EC2 swaps implementations behind those names — nothing else.
6. **Forward-compat (.rcfg):** unknown fields and unknown `ReinforcingElement.kind`s are preserved on round-trip (a v1.0.x file with `TENDON`s must survive a v1.0.0 load — §10).

### Definition-of-Done template (applies to every phase)
- [ ] All steps implemented at the stated file paths.
- [ ] All phase tests green; coverage target met (`/packages/core` ≥ 90% on solver + validation by P6).
- [ ] CI manifest-integrity gate passes (P0 onward): every manifest validates against its JSON Schema + cross-reference checks (§11).
- [ ] Engine-purity + determinism invariants hold (lint + a determinism test).
- [ ] No new `if (elementType === …)` / `if (codePack === …)` branches in `/packages/core`.
- [ ] Spec references in the phase are actually satisfied (self-check against the listed §s).

### Engineering sign-off gates (spec §11 "engineering-correctness gate" + §14)
These are **release-blocking** and are *people* dependencies, not code. Track them; do not mark a phase "done" if its gate is open:
- **G-BAEL (blocks P1 acceptance):** BAEL 91-99 constants table (§7.11) ratified by a qualified structural engineer (§14.7).
- **G-EC2 (blocks P4a):** EC2 reference cases ratified.
- **G-RPS (blocks P4b):** RPS-2011 ⚠ cells — `l_c`, critical-zone spacing per ND class, min tie ø, required confinement, zone enum + `a_g` map (§7.10b, §14.6) — ratified.
- **G-TOL (blocks P1/P4):** per-rule WARN tolerance bands (§7.12, §14.8).
- Reference-case golden suites (known inputs → expected `As`, spacing, `l_s`/`l_bd`, tie limits, cut lengths) **signed off** before the engine math is "done" (§11).

> Until a constants table is ratified, ship it as a **clearly-flagged provisional JSON** in the code pack with `"_provisional": true`; the engine reads it the same way. This keeps coding unblocked while making the open gate visible.

## Phase 0 — Pin the core contracts (spec M0, §5.2.1, §5.1.1, §0.2.1, §10, §6.1, §7.11, §11)

**Objective.** Freeze the **six core contracts** as TypeScript types + JSON Schemas + fixtures. **No feature code, no UI, no solver bodies.** Everything downstream compiles against these; changing them later is expensive, so get them right now.

**Depends on:** nothing (greenfield).

**The six contracts to pin:**
1. **Segment grammar** (§5.2.1) — `ShapeArchetype` JSON shape: `params[]`, `segments[]` op list (`line|turn|arc|hook`), `closed`, `endHooks`, `mandrelRule`, `totalLengthExpr`, `bendDeductionRule`, `plane`.
2. **Distribution** (§5.1.1) — `FIXED_COUNT` | `SPACING_ALONG_PATH` with ordered `segments[]` (`region`, `extent` expr, `spacing`); single-segment shorthand normalization.
3. **`ReinforcingElement` / `BarGroup`** serialized type (§0.2.1, §10) — discriminated union on `kind`; v1.0 only `REBAR_GROUP`. Required fields per §10's "Serialized contract".
4. **Layout-solver I/O** (§6.1) — input layout descriptor; output `{ position(u,v), faceTag, layerIndex, isCorner }[]` **plus computed `d`/`d'` per zone** (§6.1 [REF-SYS-611]).
5. **`code.*` function interface** (§7.11) — TS interface every pack implements: `mandrelMin(d)`, `bendDeduction(angle,d)`, `lbd(...)`, `l0(...)`, `AsMin(...)`, `tieSpacingMax(...)`, `cover(...)`, plus the constants accessors.
6. **Manifest JSON Schemas** (§11) — for `elements/`, `shapes/`, `schemes/`, `supplements/`, code-pack files; plus the `.rcfg` envelope schema (§10).

**Steps:**
1. Scaffold the monorepo + workspaces + Vite + Vitest + ESLint (engine-purity rule). `/packages/core/src/types/`.
2. Write TS types: `ShapeArchetype`, `SegmentOp`, `HookDescriptor`, `Distribution`, `DistributionSegment`, `ReinforcingElement`, `BarGroup`, `PlacementRule`, `LayoutDescriptor`, `LayoutResult`, `ZoneGeometry` (`d`, `d'`, centroid), `CodePack` (the `code.*` interface), `RcfgDocument` (§10 envelope).
3. Write JSON Schemas (Draft 2020-12) for every manifest type + `.rcfg`. Publish them under `/packages/core/schemas/`.
4. Author **fixtures** (no logic): one valid `.rcfg` (the §10 column example verbatim), one of each manifest type (`shapes/cadre_rect.json` from §5.2.1h, `elements/E-COL-01.json`, a ties `scheme`, a `supplements/SUPP_EPINGLE_CROSSTIE.json`), and a deliberately-broken copy of each (for negative tests).
5. Stand up the **manifest-integrity CI gate**: a script that validates every manifest against its schema + cross-reference checks (scheme → declared zones/existing shape ids/catalogued supplements; archetype `len_expr` symbols ∈ in-scope set §5.2.1f).

**Tests (Vitest):**
- `schema.valid.spec` — every good fixture validates against its schema.
- `schema.invalid.spec` — every broken fixture **fails** validation with the expected error path.
- `rcfg.roundtrip.spec` — parse the §10 fixture → serialize → deep-equal; **unknown `kind` + unknown field preserved** (inject a fake `kind:"TENDON"` and an extra field, assert survival — §10 forward-compat).
- `types.compile.spec` — a `tsd`/type-level test asserting `BarGroup` requires exactly the §10 fields and `ReinforcingElement` is a discriminated union.
- `crossref.spec` — the integrity gate flags a scheme referencing a missing zone/shape/supplement.

**Definition of Done:**
- [ ] Six contracts exist as types + schemas + fixtures; **no solver/UI/exporter bodies**.
- [ ] CI integrity gate runs and is wired into the test command.
- [ ] `.rcfg` round-trip preserves unknown kinds/fields.
- [ ] Downstream packages can `import` the types and compile.

**Risks/notes:** Resist adding logic. The single most damaging mistake is an under-specified `Distribution` or `PlacementRule` type — re-read §5.1.1 and §5.4 and make sure every placement reference target (`corners[i]`, `faces[edge]`, `barIndices[]`, `zone`, `path`, `coordinate`) and every distribution mode (`FIXED_COUNT`, `SPACING_ALONG_PATH`, `EQUAL_PERIMETER`, `LAYERED`, `SYMMETRIC`) is representable.

## Phase 1 — Engine skeleton + 1 element + BAEL pack (spec M1, §6.1, §5.2.1, §0.1, §7, §7.11)

**Objective.** A **headless** engine that solves and validates one element (`E-COL-01`, rectangular tied column) with its ties scheme, against the **BAEL-FR pack only** (EC2 deferred to P4 so two rule sets are never half-built). No UI.

**Depends on:** P0 contracts + fixtures.

**Steps:**
1. **Generic segment-grammar generator** (§5.2.1) in `/packages/core/src/geometry/`. Implements the turtle model (`line|turn|arc|hook`), local frame `(u,v,w)`, `hand`-resolved bends, `closed` welding, **mandrel fillets** (centerline radius `r = mandrelØ/2 + φ/2`), hooks (`90|135|180`, `ext_expr`, mandrel), and `mathjs` expression eval against the **frozen scope** (§5.2.1f). Emits `centerline3D`, `cutLength` (Σ straights + Σ fillet arcs + Σ hook allowances − Σ bend deductions), and `fiche` (labelled a/b/c + angles + mandrel).
2. **Layout solver** (§6.1) — rectangular path only for now: corner-bars-first with **shared corners counted once**, intermediate `nFace−2` at equal spacing, `SYMMETRIC` + `LAYERED`, clear-spacing per face/layer. Emit `{position,faceTag,layerIndex,isCorner}[]` and **computed `d`/`d'` per zone** (§6.1 [REF-SYS-611], area-weighted tension centroid).
3. **Code-pack interface + BAEL-FR pack** (§7.11): implement `code.*` for area (§7.1), clear spacing (§7.2), cover (§7.3 incl. `CAST_AGAINST_EARTH` + fire stub), column ratio limits + min bars (§7.4), tie spacing + tie-ø + **leg-counted `Asw`** (§7.5), mandrel incl. **bearing-stress check** (§7.6), anchorage/lap `l_s`/`l_r` with **`As,req/As,prov` reduction** + **auto bond classification** (§7.7). Constants live in `/packages/codepacks/BAEL-FR/` as data (flag provisional cells until **G-BAEL**).
4. **Validation engine** (§7) — each rule returns `{status, value, limit, codeRef, message_fr, message_en, affectedGroupIds[]}`. Wire the **validity layer tiers** (§0.1: hard-invalid/discouraged/free → 🔴/🟠/🟢) and the **severity policy** (§7.12).
5. **Pipeline orchestrator** (§6): `params + reinforcement → layout → shape-gen → assembly → validation → outputs`. Pure function; returns a plain `SolveResult`.
6. Author `elements/E-COL-01.json` + the **ties scheme** + `CADRE_RECT`, `DROITE`, `EPINGLE`, `ATTENTE`, `BAIONNETTE` archetypes used by columns.

**Tests (Vitest, headless):**
- **Engineering reference cases — BAEL (golden, gate G-BAEL):** known column (e.g. `b=300,h=600,H=3000`, FeE500/C25) → expected `As,provided`, `s_clear`, `c_nom`, tie `s_t,max`, `l_s` (≈40φ), `A_min`/`A_max`. Numbers committed as goldens; **signed off by the structural engineer**.
- `segment_grammar.spec` — `CADRE_RECT` (core 240×540, φ8) closes within tolerance; `cutLength = 2*(w+h)+2*hookExt − bendDeductions`; 135° hook geometry correct; fillet radius = `mandrelØ/2+φ/2`.
- `layout_corner_sharing.spec` — `nTop=nBottom=3,nLeft=nRight=2` → `N = 4 + Σ(nFace−2) = 6`, corners counted once; `nFace<2` → tier-1 hard-invalid.
- `effective_depth.spec` — `d` from the resolved tension centroid (single + multi-layer) matches hand calc, **not** `0.9h`.
- `leg_count_asw.spec` — a 2-leg `CADRE_RECT` vs +cross-tie (4-leg) doubles `Asw/s` at fixed spacing (§7.5).
- `anchorage_reduction.spec` — `As,prov > As,req` shortens `l_s`; clamped to `l_b,min`; top-bar auto-classified poor-bond.
- `validity_tiers.spec` — under-min bars, spacing < min, ratio out of range, mandrel below min → 🔴; near-limit → 🟠.
- `determinism.spec` — same input twice → identical `SolveResult`.

**Definition of Done:**
- [ ] `solve(E-COL-01 + ties)` produces centerlines, `cutLength`, `d`, validation — headless.
- [ ] BAEL golden reference cases pass **and** G-BAEL signed (or provisional cells clearly flagged).
- [ ] Engine purity holds (no DOM/React/three).
- [ ] G-TOL bands wired (provisional allowed).

**Risks/notes:** the `cutLength` (site fabrication length ≠ naive polyline) is the most error-prone piece — bake the bend-deduction sign convention into a golden test early. Keep `d`/`d'` as first-class solver outputs from day one; retrofitting them later is painful.

## Phase 2 — SPA shell + 3D viewport (spec M2, §2, §8)

**Objective.** A running web app: pick `E-COL-01`, edit geometry/material/cover/diameters/spacing, see live 3D, see live alerts, watch failing bars turn **RED**. Engine from P1 reused unchanged.

**Depends on:** P1 engine.

**Steps:**
1. `/apps/web` Vite React app. **Zustand** store holding the active `Element` document; every mutation triggers a **synchronous engine re-solve** + redraw (no reload, no network) — §2.1.
2. **R3F viewport** (§2.1/§8): concrete as semi-transparent volume (`MeshStandardMaterial`, opacity 0.30); rebar as instanced `TubeGeometry` along `centerline3D`; **failing bars recolor absolute RED**; `OrbitControls`; **section-cut plane toggle**; fit/orbit.
3. **Performance fallback (normative, §2.2):** during active drag → debounce full re-solve, render **centerline `LineSegments`** instead of rebuilding tubes, defer full validation; on drag-release → full solve + tube rebuild + validation once. Add a perf HUD (solve ms) behind a debug flag.
4. **UI shell** (§8 ASCII): navbar (element ▼, code ▼ [BAEL only for now], FR/EN, ⤓/⤒ stubbed), sidebar tabs **Schéma / Géométrie / Projet-Code**, **Armatures principales** section with per-zone Ø + count/spacing controls, **live `As,prov/As,req` badges + computed `d`/lever-arm readout** (§8). **Alerts panel** listing rule results (FR/EN), each clickable to highlight affected bars in 3D.
5. **i18n scaffolding:** FR default, EN toggle; all labels carry `_fr`/`_en`. Wire a resource-bundle mechanism even if only FR/EN columns of manifests are used yet.

**Tests:**
- `store_resolve.spec` — a param mutation produces a new `SolveResult` synchronously; store snapshot stable.
- `perf_budget.spec` — solve+validate of a typical `E-COL-01` < **16 ms** (Vitest benchmark; CI threshold).
- `red_fail_mapping.spec` — given a FAIL result, the viewport prop-mapper marks the correct `affectedGroupIds` bars red (test the pure mapping fn, not WebGL).
- `degradation.spec` — drag-mode flag switches the viewport builder from tubes to `LineSegments` and defers validation; commit restores full fidelity.
- `@testing-library` smoke: changing a diameter updates the `As,prov` badge and an alert row.

**Definition of Done:**
- [ ] App runs (`vite dev`); editing a column updates 3D + alerts live.
- [ ] Red-fail rendering works; section-cut + orbit work.
- [ ] Perf budget test green; degradation path proven by test.
- [ ] No engine logic leaked into `/apps/web` (UI only orchestrates + renders).

**Risks/notes:** keep all geometry math in `/packages/core`; the viewport must be a *dumb* renderer of arrays so it stays testable and reusable. Instancing matters for perf — use `InstancedMesh` for repeated ties.

## Phase 3 — Scheme catalog + supplements + advanced builder (spec M3, §5.3, §5.4, §5.5, §5.6, §8)

**Objective.** The "killer feature" surface: a scheme catalog, a supplemental add-on panel with **click-to-bind in 3D** (and a **keyboard/list alternative**, a11y), and the **advanced (expert) builder**. Add `E-BEM-01` (rectangular beam) as the second element to prove generality.

**Depends on:** P1 engine + P2 UI.

**Steps:**
1. **Scheme resolver** (§5.3): selecting a scheme maps its `baseGroups[]` onto the element's zones; switching schemes resets/remaps groups. Ship the indicative starter schemes (§5.3) for column (ties; ties+cross-ties; ties+diamond; lap-zone baïonnette+starters) and beam (simple span; span chapeaux+filants; bent-up; cantilever).
2. **Placement-rule resolver** (§5.4): bind groups to `corners[i]`/`faces[edge]`/`barIndices[]`/`zone`/`path`/`coordinate`; distribution modes incl. `SPACING_ALONG_PATH`. This is what makes supplements self-updating.
3. **Supplemental engine** (§5.5): `supplements/*.json` with `requires`/`placement.select`; the panel lists only the scheme's `supplementalCatalog`. **Re-solve on base change; flag WARN + prompt rebind/remove when a referenced bar is deleted.** Ship `SUPP_EPINGLE_CROSSTIE`, `SUPP_DIAGONALE_ANGLE`, `SUPP_RELEVE_BARS`, `SUPP_SKIN_SIDE`, `SUPP_DIAMANT_TIE`, `SUPP_DOUBLE_STIRRUP_SUPPORT`, `SUPP_HEAD_HOOPS`.
4. **Click-to-bind in 3D** + **list/index alternative** (§8 a11y): click two longitudinal bars → create an épingle between them; equivalently pick indices in a list (operable without a pointer).
5. **Advanced builder ("Mode expert", §5.6):** editable bar-group list — add/replace/remove any group, any archetype, explicit references/coordinates. 6. Add `elements/E-BEM-01.json` + `CHAPEAU`, `ETRIER`, `U_BAR`, `CROCHET_L`, `RELEVE` archetypes; beam validation profile (§7.4 beam `As,min` with **computed `d`**, §7.5 stirrups, §7.7 **curtailment/shift** for chapeaux + end-support anchorage).

**Tests:**
- `scheme_switch.spec` — selecting a scheme maps groups onto declared zones; switching remaps cleanly.
- `placement_resolve.spec` — `LINK_BAR_PAIR` épingle positions exactly between bars `i,j`; moving a base bar re-solves the supplement.
- `supplement_rebind.spec` — deleting a referenced base bar flags the supplement WARN and surfaces a rebind prompt.
- `beam_curtailment.spec` — chapeau `cutLength = l_support_zone + a_l + l_bd`; bottom-bar end-support anchorage ≥ `0.25·As,span` (§7.7).
- `expert_mode.spec` — advanced edits persist in `.rcfg`; tier-1 still blocks, tier-2 warns-only.
- a11y: `binding_keyboard.spec` — index-list binding produces the identical supplement as click-binding.

**Definition of Done:**
- [ ] Two elements (column + beam) fully driveable via catalog → parametrize → supplements.
- [ ] Supplements self-update on base change; broken refs WARN.
- [ ] Advanced builder works and round-trips through `.rcfg`.
- [ ] Keyboard binding parity with 3D click-binding.

**Risks/notes:** the placement-reference system (§5.4) is the backbone of "parametric, self-updating supplements" — invest here. A supplement must store **stable ids** (`group`+`barIndices`), never resolved coordinates, so a base change re-solves dependents (§10).

- `pack_swap.spec` — same element under BAEL vs EC2 produces different limits via swapped `code.*`, identical pipeline.
- `slab_rules.spec` — distribution-min FAIL; 2-way corner-torsion WARN when restrained+empty.

### Phase 4b — hardest geometries + RPS seismic overlay
**Steps:**
5. `E-STR-01` straight stair (`MARCHE_PALIER` waist+landing bend) and `E-SLB-03` hollow-block joist slab (joist + topping mesh).
6. **RPS-2011 seismic overlay** (`/packages/codepacks/seismic/RPS-2011.json`, §7.10): composable module that (1) **injects `END_*` critical-zone segments** of length `l_c` into transverse `distribution` (§5.1.1) — user spacing becomes `MIDDLE`; (2) **tightens limits** per ND class; (3) **forces 135°/≥10φ hooks** and FAILs 90° in seismic members; (4) **promotes confinement supplements to required** (validity layer blocks export until present). Rides on either BAEL or EC2 as keyed overrides.
7. **Seismic topological predicates** (§7.13): `lap_in_critical_zone` (FAIL ND2/3 when lap ∩ `l_c`), `crosstie_engagement`. **Stair predicate** `stair_reentrant_corner_pullout` (tension bar wrapping a re-entrant flight↔landing corner → 🔴/🟠).
8. **Gate G-RPS:** the ⚠ cells (`l_c`, critical-zone spacing per ND, min tie ø, required confinement, zone enum + `a_g`) **engineer-ratified** before 4b closes (§14.6). Ship provisional flagged until then.

**Tests (4b):**
- `rps_segment_injection.spec` — enabling RPS writes `END_*` (`extent=l_c`) + `MIDDLE` segments; per-segment validation (mid-span PASS while critical FAIL).
- `seismic_hooks.spec` — 135°/≥10φ forced; 90° tie → FAIL in seismic member.
- `lap_in_critical_zone.spec` — lap inside `l_c` → FAIL (ND2/3), WARN (ND1).
- `stair_reentrant.spec` — a tension bar bent around the concave kink → predicate fires; split+anchored detailing passes.
- `confinement_required.spec` — required cross-ties absent → export blocked by validity layer.
- **RPS reference cases (golden, gate G-RPS).**

**Definition of Done (P4):**
- [ ] All 8 §3.1 elements solve, validate, render.
- [ ] Both packs complete; pack swap = data swap only.
- [ ] RPS overlay composes on both packs; seismic + stair predicates fire.
- [ ] G-EC2 and G-RPS signed (or provisional clearly flagged).

**Risks/notes:** the helix generator and the stair waist+landing bend are the two disproportionately hard geometries (hence the split). Do not let RPS constants block coding — flag provisional, but **do** block the *phase close* on G-RPS.

## Phase 5 — Export engines + project I/O (spec M5, §9, §10)

**Objective.** The three on-site deliverables + persistence + the **Section/Coupe engine** (user-placed cross-section drawings). All client-side.

**Depends on:** P1–P4 (every element solvable + validating).

**Steps:**
1. **Section/Coupe engine** (§9.5, [REF-SYS-950]) — **build first; the DXF/PDF sections consume it.**
   - **Core (pure, `/packages/core`):** `SectionCut` descriptor (`origin`, `normal`, `lookBehind_mm`, `label`, `isDefault`) + `sectionAt(solveResult, cut) → CoupeView`. `CoupeView` = concrete-outline polygon (plane ∩ envelope; rectangle for a perpendicular prismatic cut, **convex polygon for an oblique cut**) + bars-in-section + dimensions + the elevation cutting-line/tag. **Free position + orientation** (the chosen scope). Bars within `lookBehind_mm` of the plane render as **nominal circles of their Ø**; a bar whose crossing angle is below the **near-parallel threshold** (§14) renders as a **line** (elevation run); group annotation `n Ø d`. The **look-behind depth** shows the nearest transverse set behind the cut (so a cut between two stirrups still shows one). Pure + deterministic — same `CoupeView` feeds preview + DXF + PDF. **Coverage: all v1.0 elements.**
   - **UI (viewport + panel):** the coupe manager — add/name/place **multiple cuts** by a **3D drag handle AND a numeric position/orientation field**, with a **keyboard/index alternative** (a11y parity, §8/§11). Seed one **default representative coupe** per element (default station per §14). Live 3D preview of the slice + the cutting-line/tag on the elevation.
2. **BBS** (§9.1): from each group's `cutLength`/count/Ø; `weight = length×count×unitMass(φ)`, `unitMass(φ)=0.006165·φ²` kg/m. Stable auto-marks; merge identical bars (shape+dims+φ) across segments. **Steel-quantity summary** (weight per Ø + steel ratio kg/m³). **Optional stock-length cut-nesting** (default 12 m stock, report waste %). Output: on-screen table + PDF *fiche de façonnage* (sketch + a/b/c + mandrel). JSON canonical record per §9.1.
3. **DXF** (§9.2), **staged**: **DXF-1 (required, release bar)** — longitudinal elevation + the **default representative coupe** (one perpendicular cross-section), fixed/templated dimension placement, the four strict layers (`COFFRAGE`/`ARMATURES`/`COTATION`/`TEXTE`). **DXF-2 (completes within M5)** — the **full coupe engine output: multiple user-defined coupes incl. arbitrary/oblique orientation** + their cutting-line/tag symbols; only the bounding-box leader-line **label-collision solver** may slip to 1.0.1 (templated label placement until then). Source geometry = the `fiche` 2D projection (§5.2, elevation) + `sectionAt` `CoupeView`s (sections), written once.
4. **PDF sheet** (§9.3): title-block (cartouche) + DXF views as vectors (**elevation + the coupe view boxes**) + BBS table + metadata + **global status stamp** (🟢/🟠). `pdf-lib`/`jspdf`. **🔴 cannot export** (export compilation locked on FAIL — §7.9).
5. **`.rcfg` I/O** (§10): save→download / import; **IndexedDB autosave + recovery**. Persist `section_cuts[]` (§9.5). `rcfg_version` gates migrations; **preserve unknown fields + unknown `kind`s + unknown cut fields on round-trip** (a tendon-bearing future file must survive).
6. Wire WARN→"À vérifier / Review required" stamp on PDF/BBS (§7.9/§7.12).

**Tests (golden-file, spec §11):**

Determinism: same `(result, cut)` → identical `CoupeView`.
