# RebarConfig v1.0 — Production Software Specification
### Web-Based Parametric Structural Detailing Platform

**Status:** Buildable specification (v1.0 scope frozen)
**Date:** 2026-06-23
**Region (v1.0):** France-Morocco. **Design basis:** dual selectable code packs — **BAEL 91 modifié 99** (default for Morocco) and **Eurocode 2 (EN 1992-1-1)** — plus **RPS 2000/2011** seismic overlay (Moroccan parasismic code). Region/code architecture is pluggable for later expansion.
**Deployment model:** Local-first, fully client-side, zero-cost hosting (static SPA). No backend in 1.0.

**Guiding principle:** RebarConfig is not a set of fixed templates — it is a **fully-parametric combination space**. Every axis (code · seismic regime · material · standard/convention · geometry · cross-section layout principle · bar shape · supplemental ties · cover/exposure · …) is an **independent, freely-combinable dimension**. The user has full control to find *any* combination that fits their case. The **only** constraint is **real construction logic** — the app allows everything buildable and blocks only what is physically or structurally invalid (see §0.1).

## 0. Executive Summary

RebarConfig is a browser-based **rebar detailing** tool (not a structural-analysis tool). The engineer supplies the required steel area (`As,req`) per zone — already obtained from analysis (ETABS/Robot/SAFE) or hand calc — and RebarConfig lets them lay out **real, construction-accurate, fully-parametric reinforcement**, see it in live 3D, get instant Eurocode-2 buildability/compliance feedback, and export the three deliverables that matter on site: **Bar Bending Schedule (BBS / nomenclature)**, **DXF detail sheets**, and a **printable PDF drawing sheet**.

The differentiator ("killer" feature) is the **parametric Reinforcement Scheme Library**: per element, a curated catalog of construction-valid reinforcement *schemes* (not just "longitudinal + stirrup"), each composed of fully-parametric **bar groups** plus a catalog of **supplemental reinforcement** add-ons (cross-ties, diagonal corner bars, bent-up bars, skin bars…). An **advanced builder** lets experts add/replace/remove bar groups freely.

## 0.1 Core Principle — The Parametric Combination Matrix [REF-SYS-050]

RebarConfig's design intent is **total parametric coverage**: the user can express any reinforcement configuration that a real detailer could draw on site. Rather than hard-wiring element→scheme combinations, the system treats detailing as the product of orthogonal **parameter axes**. A configuration is *any* point in this matrix; the app's job is to (a) let the user reach every valid point freely, and (b) refuse only the points that violate construction logic.

### Orthogonal axes (each independently selectable / parametric)
| Axis | Examples (v1.0, expandable) |
|---|---|
| **Region** | France-Morocco (more later) |
| **Concrete code** | BAEL 91-99 · Eurocode 2 |
| **Seismic regime** | None (gravity) · RPS 2000/2011 zone 1–4 + ductility class |
| **Material** | Concrete grade (fc28 / C-class), steel grade (FeE500 / B500B…), exposure |
| **Standard / convention** | French *fiche de façonnage* (BBS, bend allowances) — pluggable |
| **Element type** | column · beam · pile · slab(×3) · stair (extensible) |
| **Geometry** | section dims, height/length/span, thickness, step geometry… |
| **Cross-section layout principle** | bars-per-face, layering, symmetry, bundling, equal-perimeter (circular), mesh (slab) |
| **Bar shape design** | every ShapeArchetype (droite, crochet, baïonnette, chapeau, relevé, cadre, étrier, épingle, diamant, hélice, treillis, diagonale…) |
| **Supplemental ties / add-ons** | cross-ties, diagonal corner bars, bent-up bars, skin bars, extra hoops, densified zones… |
| **Detailing params** | cover, mandrel ø, hook type/angle, anchorage/lap lengths, aggregate size |

> The user explicitly noted that **not every option is enumerated here** — the point is the *model*, not the list. Any new option is just a new value on an axis (a manifest entry / code-pack constant), never an engine change.

### Construction-Logic Validity Layer [REF-MATH-050]
Because the matrix is huge, a dedicated layer governs which combinations are **buildable**. It has three tiers:

1. **Hard-invalid (blocked):** combinations that cannot physically exist or are structurally illegal under the active code (e.g. < min bars, spacing < min, mandrel < code min, supplement referencing a non-existent bar, helix on a rectangular section). These cannot be created/exported → 🔴.
2. **Discouraged (allowed + warned):** buildable but outside good practice or near a code limit (e.g. lap slightly short, unusual bar mix) → 🟠, exportable with a "review" stamp.
3. **Free:** everything else → 🟢.

The validity layer is **data-driven per code pack + seismic overlay**, so "what's allowed" follows the user's chosen axes. In **Guided mode** the UI only offers reachable/valid options (compatibility-filtered pickers); in **Advanced (expert) mode** the user may reach any point, with tier-1 still blocking and tier-2 warning. This is how "full control + every valid combination" and "can't build nonsense" coexist.

> 🧩 **[REF-EXT-GAP-0] — Axis & region expansion.** New regions, codes, conventions, or option values are added by extending an axis (new code pack, new manifest value) and, if needed, new validity rules. The matrix and engine are unchanged.

## 1. Document Architecture & Extension Framework

Cross-referencing system (retained and extended from the seed spec):

- `[REF-SYS-XXX]` — core system / architecture components.
- `[REF-DATA-XXX]` — data schemas & structural element variables.
- `[REF-MATH-XXX]` — mathematical / code-compliance validation rules.
- `[REF-SHAPE-XXX]` — parametric bar-shape grammar & scheme definitions.
- `[REF-EXT-GAP-X]` — explicit extension points where a domain expert inserts local geometry or regional standards.

**Extension philosophy:** elements, shape archetypes, schemes, supplemental add-ons, and code rules are all **data-driven (JSON manifests)**. Adding a new element type, a new bar shape, a new scheme, or a new code pack must require **no engine rewrite** — only new manifest entries plus (where geometry is novel) a registered shape generator.

### 2.1 Component layers
- **UI / Controls (React + TS):** component-driven; a single typed state store (Zustand or Redux Toolkit) holds the active `Element` document. Every control mutation triggers a synchronous engine re-solve and a Three.js redraw (no reload, no network).
- **3D Viewport (Three.js):** concrete as semi-transparent volume (`MeshStandardMaterial`, opacity 0.30); rebar as solid `TubeGeometry` along computed centerlines. Failing bars recolor to absolute RED. OrbitControls; section-cut plane toggle.
- **Core Engine (framework-agnostic TS):** deterministic, pure functions. Same code reused by UI, exporters, and tests. **No engine code depends on React or the DOM** — this is what makes it testable and reusable in the 1.1 server.
- **Code Pack:** the EC2-FR rule/shape/convention bundle, loaded as data. Selecting a different pack (future) swaps detailing constants, mandrel tables, anchorage formulas, shape conventions, and BBS layout.

### 2.2 Why no backend in 1.0
Free hosting, offline capability, zero per-user cost, no auth surface. The downside (no IFC, no cloud sync) is explicitly deferred. **Constraint:** the engine must therefore be performant enough to re-solve + redraw a typical element in **< 16 ms** for slider drags (target 60 fps); heavy operations (export) may take longer and run off the interaction path.

## 3. Structural Element Taxonomy [REF-DATA-200]

Object-oriented inheritance: every element extends `BaseElement`. Each element type is declared in a JSON manifest (`elements/<id>.json`) describing geometry params, reinforcement zones, compatible schemes, and the validation rule-set keys it uses.

|---|---|---|---|

| `E-COL-02` | `CIRCULAR_SPIRAL_COLUMN` | `D`, `H` | `As_total`, `Asw_spiral` (cm²/m) |
| `E-BEM-01` | `RECTANGULAR_REGULAR_BEAM` | `b`, `h`, `L` | `As_top_left`, `As_top_right`, `As_span_bottom`, `Asw_shear` (cm²/m) |

| `E-SLB-02` | `TWO_WAY_SOLID_SLAB` | `Lx`, `Ly`, `t` | `As_main_x_bot`, `As_main_y_bot`, `As_top_x`, `As_top_y` (cm²/m) |
| `E-SLB-03` | `HOLLOW_BLOCK_JOIST_SLAB` | `L`, `t_total`, `t_topping`, `b_joist`, `block_w`, `block_h`, `joist_spacing` | `As_joist_bottom`, `As_joist_top_support`, `As_topping_mesh` (cm²/m) |

**Units convention (French practice, enforced):** geometry in **mm**; steel area in **cm²** (or **cm²/m** for transverse/distributed); bar lengths in **mm** on BBS; weights in **kg**. > 🧩 **[REF-EXT-GAP-1] — Element taxonomy expansion.** New elements (`SHEAR_WALL`, `ISOLATED_FOOTING`, `STRAP_FOOTING`, `WAFFLE_SLAB`, `POST_TENSIONED_BEAM`, `RETAINING_WALL`, `L_STAIR`, `SPIRAL_STAIR`) are added by dropping a new `elements/<id>.json` manifest with the same field structure. No engine change required unless a genuinely new shape generator is needed (then register it in the shape registry, §6).

## 4. Contextual `As,req` Input Schema [REF-DATA-300]

Inputs are **zone-targeted**, never a single global number. Each element manifest declares its `As_zones[]`; the UI renders one labeled input per zone with the correct unit and a tooltip describing the structural meaning.

Example (beam `E-BEM-01`):
- `As_top_left` (cm²) — peak negative moment over left support.
- `As_top_right` (cm²) — peak negative moment over right support.
- `As_span_bottom` (cm²) — mid-span positive (sagging) moment.
- `Asw_shear` (cm²/m) — transverse steel per linear metre.

Each zone has: `key`, `label_fr`, `label_en`, `unit` (`cm2` | `cm2/m`), `kind` (`longitudinal` | `transverse`), and the **bar group(s) that satisfy it** (resolved by the scheme).

> 🧩 **[REF-EXT-GAP-2] — Zone schema expansion.** Add zones such as `As_punch` (punching shear, flat slab) or retaining-wall face zones (`As_face_earth`, `As_face_air`) by appending to the element manifest's `As_zones[]`.

## 5. Parametric Reinforcement Model — THE CORE [REF-SHAPE-500]

This section replaces and greatly expands `[REF-EXT-GAP-3]` from the seed spec. It is the heart of the product.

### 5.1 Conceptual hierarchy

```
Element
 └── Reinforcement (a chosen Scheme instance)
      ├── base bar groups[]        ← defined by the scheme
      └── supplemental bar groups[] ← user-added from scheme's supplemental_catalog
BarGroup
 ├── role: PRIMARY_LONGITUDINAL | TRANSVERSE | SUPPLEMENTAL | SKIN | DOWEL | STARTER | DISTRIBUTION
 ├── shapeArchetypeId   → ShapeArchetype (parametric segment grammar)
 ├── params {}          → values for the archetype's parameters
 ├── diameter (mm)      → from code pack's allowed set
 ├── countOrSpacing     → fixed count, OR spacing (mm) along a path
 └── placement: PlacementRule  → references host geometry (see 5.4)
```

### 5.2 Shape Archetype — parametric segment grammar [REF-SHAPE-510]

A bar shape is **data**, not code. Each `ShapeArchetype` is a JSON definition of an ordered list of **segments** connected by **bends**, plus **end hooks**. The geometry solver turns it into a 3D polyline centerline (for the Three.js tube + 3D length) and a 2D projection (for DXF + *fiche de façonnage*).

```jsonc
// shapes/baionnette.json  (crank / offset bar)
{
  "id": "BAIONNETTE",
  "label_fr": "Baïonnette (barre à décrochement)",
  "plane": "2D",                       // 2D (planar) or 3D (e.g. helix, wrapped tie)
  "params": [
    { "key": "a", "label": "Longueur basse", "type": "length", "min": 0 },
    { "key": "b", "label": "Décalage (offset)", "type": "length", "min": 0 },
    { "key": "c", "label": "Longueur haute", "type": "length", "min": 0 },
    { "key": "slope_deg", "label": "Angle du décrochement", "type": "angle", "default": 45 }
  ],
  "segments": [
    { "from": "a",       "dir": "axis+" },
    { "bend": "slope_deg", "len_expr": "b / sin(slope_deg)" },
    { "from": "c",       "dir": "axis+" }
  ],
  "endHooks": { "start": "none", "end": "none" },
  "mandrelRule": "code.mandrelMin(diameter)",   // resolved from code pack (EC2 §8.3)
  "totalLengthExpr": "a + b/sin(slope_deg) + c + hookAllowances",
  "bendDeductionRule": "code.bendDeduction"      // EC2/French allowance per bend
}
```

**Built-in archetypes shipped in v1.0 (EC2-FR pack):**

| Id | French name | Used by |
|---|---|---|
| `DROITE` | Barre droite | all |
| `CROCHET_L` | Barre à crochet (L) | beams, slabs, anchorages |
| `U_BAR` | Chaise / U | slabs, ties |
| `BAIONNETTE` | Baïonnette (crank) | columns (lap offset), beams |
| `CHAPEAU` | Chapeau (top bar over support) | beams, slabs |
| `RELEVE` | Acier relevé (bent-up) | beams (supplemental) |
| `CADRE_RECT` | Cadre rectangulaire (closed rect. tie) | columns, beams |
| `ETRIER` | Étrier (open/2-leg stirrup) | beams |
| `EPINGLE` | Épingle (single-leg cross-tie) | columns, beams (supplemental) |
| `CADRE_DIAMANT` | Cadre losange/diamant (interior tie) | columns (supplemental) |
| `SPIRALE_HELICE` | Spirale / hélice (3D helix) | circular columns, piles |
| `TREILLIS_MESH` | Treillis soudé / nappe (mesh mat) | slabs |
| `DIAGONALE_ANGLE` | Barre diagonale d'angle | columns/beams (supplemental) |
| `MARCHE_PALIER` | Barre principale escalier (waist + landing bend) | stairs |
| `ATTENTE` | Acier en attente (starter/dowel) | columns, stairs, piles |

Each archetype emits:
- **`centerline3D`** — ordered `[x,y,z]` points (bends approximated as poly-arcs at the mandrel radius for fidelity).
- **`cutLength`** — fabrication length per code pack (segment sum ± bend deductions + hook allowances).
- **`fiche`** — the *fiche de façonnage* representation: ordered segments with labeled lengths `a,b,c…`, bend angles, mandrel ø, sketch hints.

> 🧩 **[REF-EXT-GAP-3] — Bar archetype routing.** New shapes (e.g. multi-leg confinement hoops with seismic 135° hooks, Z-bars, trombones) are added as new `shapes/<id>.json` + an optional registered generator function if the segment grammar can't express them declaratively. The grammar covers all planar bent bars and parameterized helices natively.

### 5.3 Reinforcement Scheme [REF-SHAPE-520]

A **Scheme** is a curated, construction-valid composition for a specific element. It is the unit the user picks from the catalog.

```jsonc
// schemes/E-BEM-01/travee-chapeaux-releves.json
{
  "id": "BEAM_SPAN_CHAPEAUX_RELEVES",
  "elementType": "E-BEM-01",
  "label_fr": "Travée — chapeaux + aciers filants + cadres",
  "thumbnail": "…",
  "baseGroups": [
    { "role": "PRIMARY_LONGITUDINAL", "zone": "As_span_bottom", "shape": "DROITE",
      "placement": { "rule": "BOTTOM_LAYER", "count": "param" } },
    { "role": "PRIMARY_LONGITUDINAL", "zone": "As_top_left",  "shape": "CHAPEAU",
      "placement": { "rule": "TOP_LEFT_SUPPORT" } },
    { "role": "PRIMARY_LONGITUDINAL", "zone": "As_top_right", "shape": "CHAPEAU",
      "placement": { "rule": "TOP_RIGHT_SUPPORT" } },
    { "role": "TRANSVERSE", "zone": "Asw_shear", "shape": "CADRE_RECT",
      "placement": { "rule": "ALONG_LENGTH", "spacing": "param" } }
  ],
  "supplementalCatalog": [
    "SUPP_RELEVE_BARS", "SUPP_SKIN_SIDE", "SUPP_EPINGLE_TOP",
    "SUPP_DOUBLE_STIRRUP_SUPPORT"
  ],
  "validationProfile": "EC2_BEAM"
}
```

Per element, v1.0 ships **2–4 schemes minimum** (the framework allows unlimited). Indicative starter catalog:

- **Rect. column:** ties only; ties + cross-ties; ties + interior diamond; lap zone with baïonnette + starters.
- **Circular column:** continuous spiral; spiral + extra head hoops.
- **Beam:** simple span (straight + cadres); span with chapeaux + filants; with bent-up bars; cantilever.
- **Pile:** longitudinal cage + spiral; cage + head dowels.
- **1-way slab:** bottom mat + top chapeaux at supports; with distribution emphasis.
- **2-way slab:** bottom mats X/Y + top mats at supports.
- **Hollow-block slab:** joist bottom + top support bars + topping mesh.
- **Stair:** straight flight (bottom main + chapeaux at top + starters + distribution); with intermediate landing.

### 5.4 Placement Rules & Host-Geometry References [REF-SHAPE-530]

`PlacementRule` is how a bar group is positioned **relative to the element and to other bars** — this is what makes supplements parametric and self-updating.

Reference targets a placement can bind to:
- **`corners[i]`** — corner index of the section (rect: 0–3; from the longitudinal layout).
- **`faces[edge]`** — `TOP|BOTTOM|LEFT|RIGHT` (rect) or angular position (circular).
- **`barIndices[i,j,…]`** — specific primary longitudinal bars (e.g. an *épingle* links bars `i` and `j`).
- **`zone`** — a named reinforcement zone (`As_top_left`, support region, mid-span…).
- **`path`** — a curve along which transverse bars repeat (column height, beam length, spiral axis).
- **`coordinate`** — explicit offset (advanced builder only).

Distribution modes: `FIXED_COUNT`, `SPACING_ALONG_PATH`, `EQUAL_PERIMETER`, `LAYERED` (multi-row with inter-layer clear gap), `SYMMETRIC`.

This reference system is what enables the **2D, multi-layer** column/beam cross-section layout (the seed spec's §5.2 1-D formula is generalized — see §7.2).

### 5.5 Supplemental Reinforcement [REF-SHAPE-540]

A **supplemental group** is a `BarGroup` with `role: SUPPLEMENTAL` (or `SKIN`/`DOWEL`) whose placement **references the resolved base layout**. The scheme's `supplementalCatalog` lists which are construction-valid for that scheme; the user adds them from a dedicated **"Armatures complémentaires"** panel, then parametrizes them.

```jsonc
// supplements/SUPP_EPINGLE_CROSSTIE.json
{
  "id": "SUPP_EPINGLE_CROSSTIE",
  "label_fr": "Épingle (cadre intermédiaire)",
  "role": "SUPPLEMENTAL",
  "shape": "EPINGLE",
  "requires": { "hostRole": "PRIMARY_LONGITUDINAL", "min_bars": 4 },
  "placement": {
    "rule": "LINK_BAR_PAIR",
    "select": "user",            // user clicks two longitudinal bars in 3D / picks indices
    "spacing": "= tie.spacing"   // follows the tie spacing along the height by default
  },
  "params": [
    { "key": "diameter", "type": "diameter", "default": 8 },
    { "key": "hook_angle", "type": "angle", "default": 135 }  // EC2 seismic hook option
  ],
  "validation": ["spacing_with_base", "hook_anchorage"]
}
```

Examples shipped v1.0:
- **`SUPP_EPINGLE_CROSSTIE`** — épingle linking an interior bar pair (column/beam).
- **`SUPP_DIAGONALE_ANGLE`** — diagonal/inclined bar at a section corner (your column example).
- **`SUPP_RELEVE_BARS`** — bent-up bars (aciers relevés) in beams.
- **`SUPP_SKIN_SIDE`** — armatures de peau on tall sections.
- **`SUPP_DIAMANT_TIE`** — interior diamond confinement tie.
- **`SUPP_DOUBLE_STIRRUP_SUPPORT`** — densified stirrups in support/joint zones.
- **`SUPP_HEAD_HOOPS`** — extra hoops at pile/column head.

**Behaviour:** when a base bar moves (param change), every supplement bound to it re-solves automatically. If a referenced bar is deleted, the supplement is flagged invalid (WARN) and the user is prompted to rebind or remove it. The 3D canvas lets the user **click base bars to define a supplement's references** (e.g. click two bars → create an épingle between them).

> 🧩 **[REF-EXT-GAP-5] — Supplemental archetype expansion.** New supplemental add-ons are added as `supplements/<id>.json` + listed in any scheme's `supplementalCatalog`. The `requires`/`placement.select` fields keep them construction-valid.

### 5.6 Authoring modes [REF-SHAPE-550]
- **Guided (default):** pick element → pick scheme → set geometry → set diameters/counts/spacings per zone → add supplements from the catalog. The validator prevents non-buildable states.
- **Advanced builder:** "Mode expert" toggle reveals the bar-group list; the user can add/replace/remove any group, choose any archetype, and place via explicit references/coordinates. Validation still runs but warnings (not hard locks) are permitted so experts aren't blocked. **Custom scheme *saving* is not in v1.0** (1.1 with accounts) — but an advanced layout persists fully inside the `.rcfg` project file.

## 6. Geometry Solver & Shape Registry [REF-SYS-600]

The solver is a pipeline (pure functions):

```
Element params + Reinforcement(scheme + groups)
   │
   ▼ 1. Layout solver  → positions of each bar in the cross-section / along paths
   │     (handles layers, covers, stirrup offset, equal spacing, symmetry)
   ▼ 2. Shape generator → for each bar group, build centerline3D + cutLength + fiche
   │     (looks up ShapeArchetype; resolves params, mandrel, hooks via code pack)
   ▼ 3. Assembly        → full 3D bar set (instanced), concrete envelope mesh
   ▼ 4. Validation      → run code rule-set → per-group + element status
   ▼ 5. Outputs         → viewport meshes, BBS records, DXF projections, PDF model
```

**Shape registry:** a map `archetypeId → generator`. Most archetypes are handled by the **generic segment-grammar generator**; only genuinely special ones (helix, mesh) register a bespoke generator. This is the single extension seam for novel geometry.

## 7. Validation & Code-Compliance Engine [REF-MATH-700]

Replaces seed §5. Validation runs on every state change (target < 16 ms). Each rule returns `{status: PASS|WARN|FAIL, value, limit, codeRef, message_fr, message_en, affectedGroupIds[]}`.

**Code-pack driven.** The rules below are stated with Eurocode-2 references for concreteness, but every constant and formula is supplied by the **active code pack**. v1.0 ships two packs whose values differ:
- **BAEL 91-99** (default, Morocco): cover/enrobage, `l_s` scellement/anchorage (`l_s = φ·f_e/(4·τ_su)`), lap lengths, `A_min`/`A_max` per BAEL/CBA 93, min bar counts, tie spacing rules, French bar grades (FeE500 → `f_e`, concrete `f_c28`).
- **Eurocode 2 (EN 1992-1-1)**: the §7.1–7.8 formulas as written (`l_bd`, `l_0`, ρ-limits, `s_cl,tmax`, mandrel 4φ/7φ, cover `c_min+Δc_dev`).

Each rule carries a `codeRef` so alerts cite the exact clause of whichever pack is active. The **construction-logic validity layer (§0.1 / [REF-MATH-050])** sits above these rules and assigns the hard-block / warn / free tier.

### 7.1 Provided area (per zone)
$$A_{s,\text{provided}}^{(z)} = \sum_{i \in \text{group}(z)} n_i \cdot \frac{\pi \phi_i^2}{4}$$
summed over the bar groups assigned to zone `z`. **FAIL** if `< As_req(z)`.

### 7.2 Clear spacing — generalized (multi-layer, 2D)
The seed §5.2 1-D formula is generalized. For a layer of `N` equal bars on a face of clear width `W`:
$$s_{\text{clear}} = \frac{W - 2c - 2\phi_{t} - N\phi_{\ell}}{N - 1}$$
where `c` = nominal cover, `φ_t` = transverse (stirrup) diameter, `φ_ℓ` = longitudinal diameter. For multiple layers, the **vertical clear gap** between layers is checked the same way. For circular/spiral, spacing is checked along the pitch circle perimeter. **EC2 §8.2 minimum:**
$$s_{\text{clear,min}} = \max(\phi_\ell,\; d_g + 5\text{ mm},\; 20\text{ mm})$$
where `d_g` = max aggregate size (user input, default 20 mm). **FAIL** if `s_clear < s_clear,min`.

### 7.3 Cover (EC2 §4.4)
`c_nom = c_min + Δc_dev` (Δc_dev default 10 mm). `c_min ≥ max(φ, c_min,dur(exposure class), 10 mm)`. Exposure class is a user input (XC1…XS3). **FAIL** if user cover < `c_nom`.

### 7.4 Reinforcement ratio limits
- **Columns (EC2 §9.5):** `As,min = max(0.10·N_Ed/f_yd, 0.002·A_c)` — *N_Ed optional; if absent, use 0.002·Ac*; `As,max = 0.04·A_c` (0.08 at laps). Min bars: **4** (rect), **6** (circular). **FAIL** outside range.
- **Beams (EC2 §9.2):** `As,min = max(0.26·(f_ctm/f_yk)·b·d, 0.0013·b·d)`; `As,max = 0.04·A_c`.
- **Slabs (EC2 §9.3):** `As,min` as beams; **max bar spacing** `s_max` ≤ min(3h, 400 mm) (principal), ≤ min(3.5h, 450 mm) (secondary).

### 7.5 Transverse / confinement (EC2 §9.5.3 columns, §9.2.2 beams)
- Column tie spacing `s_cl,tmax = min(20·φ_ℓ, b_min, 400 mm)`; ×0.6 in joint/lap zones.
- Tie diameter ≥ max(6 mm, φ_ℓ/4).
- Beam max stirrup spacing `s_l,max = 0.75·d`.
Compare against user spacing; **WARN/FAIL** accordingly. `Asw,provided/m` vs `Asw,req` per zone.

### 7.6 Mandrel diameter / bend feasibility (EC2 §8.3)
Min mandrel ø: **4φ** (φ ≤ 16 mm), **7φ** (φ > 16 mm). The fiche/cutLength uses these; if a user-set bend radius is smaller → **FAIL** (cracking risk).

### 7.7 Anchorage & lap lengths (EC2 §8.4, §8.7)
Compute `l_bd` (design anchorage) and `l_0` (lap) from φ, bond conditions, and material (f_ck, f_yk user inputs with French defaults C25/30, B500B). Hooks/baïonnette segment lengths must satisfy `l_bd`; lap zones must satisfy `l_0`. **WARN** if hook/lap shorter than required.

### 7.8 Aggregate vs spacing
`s_clear ≥ d_g + 5 mm` (folded into §7.2).

### 7.9 Deterministic UI status (seed §5.3, refined)
- **🟢 PASS** — all rules PASS. All export triggers enabled.
- **🟠 WARN** — no FAIL, but ≥1 WARN (e.g. lap slightly short, spacing near limit). Exports **enabled** but PDF/BBS stamped "À vérifier / Review required" and the alert panel lists warnings.
- **🔴 FAIL** — ≥1 FAIL (insufficient steel, spacing < min, ratio out of range, bend infeasible). Failing bars render **RED** in 3D; **export compilation is locked**; alert panel explains each failure with the value and the EC2 limit.

### 7.10 Seismic overlay — RPS 2000/2011 [REF-MATH-710]
A **seismic overlay** activates when the user sets a seismic regime (RPS zone 1–4 + ductility class ND1/ND2/ND3). It is applied *on top of* the chosen concrete code (BAEL or EC2) and modifies/adds rules:
- **Critical (plastic-hinge) zones** auto-derived at member ends/joints (length `l_c` per RPS), shown shaded in 3D.
- **Tie/stirrup densification** in critical zones: reduced spacing `s = min(8·φ_ℓ, b/2, …)` per RPS table for the ductility class; **FAIL** if user spacing exceeds it in those zones.
- **135° seismic hooks** required on ties/cross-ties/épingles (hook extension ≥ 10φ); the supplemental-tie engine offers 135° by default under RPS and **WARN/FAIL**s on 90° hooks.
- **Confinement add-ons** (cross-ties/diamond ties) become *required* (not optional) for the section's bar arrangement; the supplemental panel pre-loads them.
- **Min longitudinal ratio** and **max tie spacing** tightened per RPS ductility class.

When seismic = None, the overlay is inert (pure gravity detailing). The overlay is a separate data module (`codepacks/seismic/RPS-2011.json`), keeping it composable with either concrete code.

> 🧩 **[REF-MATH-700 / code-pack hook]** All limits/formulas above live in the active **code pack** (BAEL-FR / EC2) plus the optional **seismic overlay** (RPS-2011) as data + named functions. A future pack (ACI 318 + ASCE 7, BS 8666, other regions/seismic codes) supplies its own constants/formulas and overlay without touching the engine. This is the seed's `[REF-EXT-GAP-4]` realized as a pluggable layer, aligned with the combination-matrix axes (§0.1).

## 9. Export Engines [REF-SYS-900]

All client-side in v1.0.

### 9.1 BBS — Nomenclature d'armatures
Builds from each bar group's `cutLength`, count, diameter; weight = `length × count × unitMass(φ)` (kg/m table). Output: on-screen table + PDF, French *fiche de façonnage* style (shape sketch + a/b/c dims + mandrel). JSON form (per seed §7.2) is the canonical record:

```jsonc
{
  "element_summary": { "element_id": "B12", "total_weight_kg": 89.15 },
  "bar_records": [
    { "mark": "01", "shape": "DROITE",     "diameter_mm": 16, "length_mm": 5450, "quantity": 4,  "weight_kg": 34.42, "fiche": {…} },
    { "mark": "02", "shape": "CADRE_RECT", "diameter_mm": 8,  "length_mm": 1640, "quantity": 28, "weight_kg": 18.11, "fiche": {…} }
  ]
}
```
Marks are auto-assigned and stable; identical bars (same shape+dims+φ) merge to one mark with summed quantity.

### 9.2 DXF detail sheets
Project the 3D centerlines onto 2D planes (longitudinal elevation + cross-sections). Generated client-side (`@tarikjabiri/dxf` or equivalent). Strict layers:
- `COFFRAGE` — concrete formwork outline (grey, continuous).
- `ARMATURES` — bold rebar lines.
- `COTATION` — dimensions.
- `TEXTE` — annotations.
- **Label collision avoidance:** each annotation (e.g. `4 Φ 16 L=5450 e=15cm`) has a 2D bounding box; a tracker offsets overlapping labels with leader lines.

### 9.3 PDF drawing sheet
Title-blocked sheet (cartouche) bundling DXF views (as vectors) + the BBS table + project metadata + the global status stamp (🟢/🟠). Generated with `pdf-lib`/`jspdf`. Failing (🔴) state cannot export.

### 9.4 IFC — deferred to 1.1
`IfcReinforcingBar`/`IfcReinforcingMesh` (IFC4) via a server-side FastAPI + IfcOpenShell service, enabled only when cloud/accounts ship.

> 🧩 **[REF-EXT-GAP-4] — Regional detailing standards.** Bend formulas, shape-code books (BS 8666 numeric codes, ACI 315), and BBS layouts live in the code pack's `convention` module. The French *fiche* is the v1.0 convention; 1.0.1 adds others as data + a convention selector.
