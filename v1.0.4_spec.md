## 0. Goal, scope & invariants

### 0.1 The goal this spec completes
From `core_logic.md`: turn *"how much steel does this need?"* into a **buildable, code-checked, site-ready** rebar
design (3D + BBS + drawings), **instantly, in the browser**, on a **generic, data-driven engine**. The machinery
exists; three promises are not yet fully true and this spec makes them true:
- **"code-checked"** — the numeric layer is *provisional* (no engineer sign-off), EC2 is *unreachable from the UI*,
  and *anything that adds/removes steel bypasses the checks*. → **Track A** + the façonnage validity items.
- **"buildable"** — detailing add-ons skip spacing/anchorage/As; splices are group-level; supports are
  representative. → **Track A/B** + façonnage.
- **"site-ready"** — coupe conventions are provisional, coupes are representative for slab-family, the drawing has
  sketch/dimension gaps, the 3D is representative in places. → **Track C/D**.

### 0.2 Scope
**IN:** façonnage-flow hardening (H1–H19); Tracks **A** (A1 sign-off *harness* + A2 validation completeness + A3
multi-code reachability), **B** (B1 splice stagger + B2 support precision + B3 add-on fidelity), **C** (C1 coupe
exactness + C2 shop-drawing completeness), **D** (D1 stair + D2 fidelity pass), **E** (E1 canonical `.rcfg` + E2
migration hardening). **OUT:** accounts/cloud/teams/IFC/building-model (Track H — later); new element types & new
code rule-sets beyond BAEL/EC2 wiring (Track G — later); the *enforced* coverage-gate widening + perf-scaling
harness as standalone infra (Track F — roadmap), though their per-feature equivalents are invariants here.

### 0.3 Hard invariants (do not violate — carried from all prior specs)
1. **Engine purity & data-driven** (v1.0 §2, §0.1). No React/three/DOM in `packages/core`; no new
   `if (elementType===…)` / `if (codePack===…)`. New behaviour rides the existing seams (shape registry,
   placement model, transverse-segment model, validation profiles, the `CodePack`/`SeismicOverlay` contracts).
2. **Determinism.** Pure solver; byte-identical output per input; no `Date.now()`/`Math.random()` in core.
3. **`cutLength` invariant (D-P1-1).** `cutLength = Σ legs + Σ hookExt − Σ bendDeduction`, cross-checked vs
   `totalLengthExpr`; strengthened by H3 (positive-finite guard in the core generator).
4. **`.rcfg` forward-compat (NORMATIVE, v1.0 §10).** Unknown `kind`s + unknown fields preserved on round-trip
   (the TENDON slot). All new persisted data is **additive**; a prior-version file loads via legacy defaults.
5. **Code-pack agnosticism (D-P1-3).** Core never imports a pack; BAEL/EC2 swap behind the same `code.*` names.
6. **Engineering correctness is human-gated.** Numeric constants ship `"_provisional":true` until the nominated
   engineer ratifies them (§0.5, `[OWNER-DEP]`). Code proceeds against provisional constants; *acceptance* waits.

### 0.4 Cross-cutting quality bar (every feature in this spec ships with all of these)
- **Tests:** each item lands with the named specs; **`npm run check` green** (purity → manifests → typecheck →
  typecheck:web → tests); **no BBS/cutLength golden moves for a legacy doc** (byte-identical is the acceptance bar
  for every "legacy no-op" claim).
- **a11y parity:** every new pointer action has a keyboard/numeric twin; **axe clean** (closes the standing P6
  a11y gate). All new UI uses the typed i18n bundle (FR/EN).
- **Perf budget:** the solve→place→BBS loop stays **< 16 ms** for representative docs, incl. addressable-heavy
  and multi-element cases.
- **Coverage:** core-only gate ≥ 90% (unchanged); the adapter is characterized (`prep_results` P0.3) and its
  `coverage:adapter` number must not regress below ~96%.

### 0.5 The data spine — sourced, not provisional (`[OWNER-DEP → owner_tasks §B/§C]`)
**Policy (owner, 2026-07-05): no invented/provisional constants.** The code-pack numbers are taken from the
published standards (BAEL 91-99, EN 1992-1-1, RPS 2011), compiled with citations in **`structural_data.md`** — the
authoritative source the pack JSON is filled from. Two consequences vs the earlier draft:
- **`As` and effective depth `d` are exact geometry** — `As = Σ(π/4)·Øᵢ²`; `d` = distance to the **area-weighted
  centroid of the bar cross-sections** (owner ruling; matches `D-P1-5`). Mixed diameters / mixed levels are handled
  exactly — **A2/H5 carry no placeholder**.
- **The remaining `[OWNER-DEP]` items are genuine inputs, not guesses:** the values only the owner/engineer can
  supply (the RPS 2011 zone→ND mapping; the National-Annex + market choices; the business defaults — see
  `structural_data.md §6`) and a **professional validation** that the app *applies* the sourced code correctly
  (the A1 reference-case suite exists for that review). **No new sign-off gate** beyond G-BAEL/EC2/RPS/COUPE/TOL.

# PART I — Façonnage flow hardening (H1–H19)

*The editor + addressable-bar channel are built (v1.0.3) but accept inputs they silently ignore, can crash, and
expose a fraction of the model. Full per-item prose + phasing: `v1.0.4_impl_plan.md`. Verified live in
`prep_results` P0.2/P0.3.*

## I.A Correctness / crash / data-loss (must-fix)

- **H1 — Per-bar override inherits the group's façonnage params (crash fix).** `buildLongOverrides`
  (`solveDoc.ts`) falls back to `{L:memberLen}` instead of the group's resolved params and always regenerates, so a
  **Ø-only override on a façonné group throws** (`expr eval failed for "lower": Undefined symbol lower`, verified).
  **Fix:** pass `groupParams = faconnageParams(group.faconnage, {L})` as the fallback; skip regen only for
  axial-only/removed-only overrides (Ø/length DO affect `cutLength`); wrap `solveDoc` in `withDoc` (`useStore.ts`)
  with keep-last-good + a non-blocking banner (`[OWNER-DEP → owner_tasks §A: H1.3 UX]`). **Tests:**
  `bar_override_inherits_faconnage`, `store_solve_guard`; flips the `p02_verify`/characterization H1 cases.
- **H2 — Unique `length` has a defined meaning for every shape.** Only DROITE has an `L` param, so `length` is a
  silent no-op on bent bars (verified). **Fix `[OWNER-DEP → §A: H2 semantic; §A: symmetric-shape principal leg]`:**
  add a `totalLengthParam` hint per open manifest; the adapter maps `length` onto that leg by inverting the linear
  `totalLengthExpr` so `cutLength == length`; disable the field where no param is authored. **Tests:**
  `unique_length_semantics`; flips `p02_verify`/characterization H2.
- **H3 — Core-level `cutLength > 0` guard.** Move the positive-finite check from the editor into
  `generateBarShape` (after the `totalLengthExpr` cross-check) so BBS/DXF/splice are all protected. **Test:**
  `cutlength_positive_guard`.
- **H4 — Editor buffer resync on shape + member-length + committed-params.** Resync
  `FaconnageEditor` on `[shapeId, memberLength, committedKey]` with a last-committed ref; fixes the
  geometry↔façonnage desync on import / geometry edit. **Test:** `faconnage_resync`.
- **H5 — Removing a bar reconciles the schedule count with As** (exact — folds into Track **A2**).
  `provided_area` reads `layout.count` (`validation/index.ts:139`), ignoring `longBars`. **Fix:** recompute per-zone
  `As,prov = Σ(π/4)·Øᵢ²` from `longBars` (excl. `removed`); mixed-Ø and mixed-level `d` are **exact** via the
  area-weighted centroid (owner ruling, `structural_data.md §1`) — no placeholder. **Test:** `removal_reconciles_as`.

# PART II — Track A: make "code-checked" true

## A1 — Fill the packs from `structural_data.md` + a validation reference-case suite  `[OWNER-DEP → §B/§C]`
**Why.** The pack constants were provisional guesses. The owner's policy is to replace them with the **sourced
values in `structural_data.md`** (BAEL/EC2/RPS, cited) — and to give a qualified engineer an executable suite to
confirm the app *applies* them correctly.
**Zayd implements:**
- **Fill the pack JSON** (`packages/codepacks/src/{bael,ec2}`) + the RPS overlay from `structural_data.md`:
  mandrel (EC2 4Ø/7Ø; BAEL R≥5.5Ø/3Ø), bond `fbd`/`τsu`, anchorage `lbd`/`ls`, lap `l0`, the α1–α6 coefficients,
  clear spacing (`max(k1·Ø, dg+k2, 20)`), cover-by-class, hook allowances (10Ø/70 mm; BAEL 2Ø return), and the RPS
  critical-zone rules (`lc = max(he/6, hc, 45cm)`; `s = min(8ØL, 0.25bc, 15cm)`). Drop the `"_provisional":true`
  flags for values now sourced; keep it **only** on the `⛳ OPEN` items until the owner supplies them (RPS zone→ND
  mapping; NA/market choices).
- **Reference-case suite** (`reference_cases_{bael,ec2,rps}`): fully-specified elements + expected per-rule
  verdicts/values, deterministic (pure engine), for the engineer to sign against.
- **A sign-off record** (`ratification.json`: pack, standard version, signer, date, suite id) read by the UI/PDF;
  the "⚠ provisoire" pill shows only for `⛳ OPEN` cells and flips to "conforme — vérifié (signer, date)" once the
  engineer signs the suite.
**Owner/engineer supply `[OWNER-DEP → §B/§C]`:** the `⛳ OPEN` data (RPS zone→ND mapping, NA/market, business defaults —
`structural_data.md §6`); a professional validation of the reference-case suite; the signer identity.
**Testing:** `reference_cases_{bael,ec2,rps}`; `pack_values_match_source` (asserts the JSON equals
`structural_data.md`). **Deliverables:** filled packs, the suites, `ratification.json` + UI/PDF wiring.
**Legacy no-op:** existing shape/BBS goldens hold unless a sourced constant legitimately changes a number — any
such change is **called out + re-baselined intentionally** (e.g. BAEL `ls` 40Ø↔44Ø per the owner's choice).

## A2 — Validation completeness: every steel add/remove feeds the checks
**Why (systemic).** A whole class of edits changes render + schedule but **not** §7: per-bar overrides / extras /
removed bars (`D-V103-4`), per-region Asw (uses representative `tz.spacing`, `D-V102-5`), relevés/supplements/
cross-ties (add-ons, `D-V103-5`, `D-P3-6`). This undermines the product's core promise ("change a bar → the verdict
updates").
**Zayd implements (all exact — per the owner's centroid ruling, no placeholder):**
- A single **steel-accounting pass** that reconciles *every* placed bar (group, override, extra, relevé,
  supplement) into per-zone **As,prov** = `Σ(π/4)·Øᵢ²` (exact, mixed-Ø included) and per-region **Asw** (extends H5
  from removal-only to the full set).
- **Effective depth `d` = area-weighted centroid** of the tension bars (`structural_data.md §1`; matches `D-P1-5`) —
  correct for mixed diameters and mixed section levels, computed from the real placed bars. **Reuse the existing
  per-zone `ZoneGeometry.tensionCentroid`/`d` convention (`D-P1-5`, `pipeline/element.ts`)** — A2 *extends* it to the
  full placed set (overrides/extras/add-ons), it does **not** re-derive which face is in tension (that convention is
  already fixed per validation profile; don't invent a new one for columns).
- **Per-region Asw verification** (replace the representative-spacing shortcut): Asw/clear-spacing per transverse
  region.
- **Clear-spacing over the real placed set** (folds H8's spacing predicate into the general validator so
  add-ons/extras are no longer exempt), using the sourced limit `max(k1·Ø, dg+k2, 20)` (EC2) / BAEL equivalent.
**Owner supply `[OWNER-DEP → §C]`:** only inputs, not rules — `dg` (aggregate size) + the NA `k1/k2`
(`structural_data.md §6`). The **which-bars-count-per-zone** region split follows each element's validation profile;
edge conventions are confirmed in the A1 engineer review (no invented constant).
**Testing:** `steel_accounting` (per-zone As + `d` from the full placed set, mixed-Ø), `per_region_asw`,
`clear_spacing_addons`. **Deliverables:** the accounting pass + per-region Asw + spacing wiring in `packages/core`
validation. **Legacy no-op:** a doc with no add-ons/overrides/regions → the grouped §7 path, byte-identical.

## A3 — Multi-code reachability (make "chosen by axis" real)
**Why.** `core_logic §8` promises "pick a code, validation re-runs" and "BAEL↔EC2 changes only the numbers", but
the adapter is typed `BaelPack` and **EC2 is unreachable from the UI**.
**Zayd implements:** widen the adapter typing `BaelPack → CodePack` (core already never imports a pack, `D-P1-3`);
a **code picker** (BAEL/EC2) in the Projet/Code tab, stored on the doc + `.rcfg` (additive); confirm the RPS
overlay composes on either base pack end-to-end; a golden proving BAEL↔EC2 changes numbers, not structure.
Builds on **H13** (single active pack).
**Owner supply `[OWNER-DEP → §A + §B]`:** default code (BAEL), and the EC2 constants stay provisional until G-EC2.
**Testing:** `code_picker` (doc/rcfg round-trip), `bael_ec2_structure_identical`. **Deliverables:** the picker,
`CodePack`-typed adapter, store `activePack` (+H13). **Legacy no-op:** default BAEL → identical numbers.

# PART III — Track B: finish the detailing depth

## B1 — Lap-splice staggering (per-bar, critical-zone)
**Why.** Splices are group-level ("all bars splice at one station → the `lap_stagger` WARN", `D-V103-6`); real
construction staggers laps, and coincident laps in a seismic critical zone are a fault.
**Zayd implements:** staggered **per-bar** splices on the addressable channel; the **stagger rule is sourced** (EC2
§8.7.2: ≤ 50 % of bars lapped at one section — `α6 = 1.5` beyond that — with adjacent laps offset ≥ 0.3·l0;
`structural_data.md §2`); the `lap_stagger` WARN becomes a PASS when met; the seismic `lap_in_critical_zone`
becomes exact per bar; rides H14's per-bar auto-split.
**Owner supply `[OWNER-DEP → §B]`:** professional confirmation of the stagger rule for the target market
(the EC2 value is the default; BAEL/RPS may qualify it) — a validation item, not an invented number.
**Testing:** `splice_stagger` (per-bar stations, ≤50%/section, 0.3·l0 offset, D-P1-1 preserved, seismic exact).
**Deliverables:** per-bar splice in `geometry/splice.ts` + the pipeline. **Legacy no-op:** unspliced docs
byte-identical.

## B2 — Beam two-support precision (placement + per-support anchorage)
**Why.** `D-V103-5`: the 2nd support's chapeau + relevés render at a **representative** axial position, and
`end_support_anchorage` is checked **once**, not per support.
**Zayd implements:** precise per-support **axial placement** of the 2nd chapeau + relevés (they never share a
cross-section); **per-support anchorage validation** (each support its own `lbd`/`ls` check, off the sourced pack —
`structural_data.md §2/§3`). Rides the existing supports data + addressable channel; no element branch.
**Testing:** `beam_support_precision` (axial positions + two anchorage checks). **Deliverables:** placement +
validation wiring. **Legacy no-op:** symmetric single-support beams unchanged.

## B3 — Supplement / add-on 3D fidelity & anchoring
**Why.** G5 anchored *épingles* + rendered their hooks, but the broader supplement placement was historically
centred-for-presence (`D-P3-6`); skin bars / diamond ties / U-bar levels need real anchored geometry.
**Zayd implements:** extend the anchored-placement seam (`MemberPlacement.transverse[].anchor`, `D-V102-2`) to
**every** supplement archetype so each renders in its true position + shape; feed them into A2's accounting.
**Testing:** `supplement_anchored_all` (each archetype anchored, not centred). **Deliverables:** placement seam
extension. **Legacy no-op:** épingles unchanged (already anchored).
