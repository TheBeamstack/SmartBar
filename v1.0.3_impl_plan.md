## Global Context (read once — this is what makes the plan self-sufficient)

### Product in one paragraph
RebarConfig is a **client-side rebar *detailing*** SPA. The user supplies `As,req` per zone, picks an element +
scheme, parametrises bars/ties, sees live 3D + BAEL/EC2/RPS buildability checks, and exports **BBS + DXF + PDF**.
No backend. Units SI internally (mm, mm², mm²/m); UI converts at the edge.

### Monorepo & gate
- `packages/core` (pure engine, NO DOM/React/three), `packages/codepacks` (BAEL/EC2/RPS), `packages/exporters`
  (BBS/DXF/PDF/.rcfg + `fiche.ts`), `apps/web` (React 18 + Vite + Zustand + R3F/three), `tests/` (core+golden).
- **Run the app:** `cd apps/web && npm run dev` → http://127.0.0.1:5180.
- **Gate (must stay green every phase):** `npm run check` = `check:purity` → `check:manifests` → `typecheck` →
  `typecheck:web` → `test` (vitest, core=node + web=jsdom). Plus `npm run coverage` (≥90% core solver+validation)
  and `npm run build:web` (proves browser-bundleability). Node 20 / npm 10, no pnpm.
- **Baseline at start of v1.0.3:** the v1.0.2 gate is green at **78 files / 387 tests** (verify with a clean
  `npm run check` before touching anything; if it isn't green, STOP and report).

### Non-negotiable invariants (verify EVERY phase)
1. **Engine purity** (no React/three/`window`/`document` in `packages/core`) + **no `if(elementType)`**.
2. **Determinism** (pure solver, byte-identical for a given input).
3. **`cutLength` invariant (D-P1-1):** every bar keeps `Σ legs + Σ hookExt − Σ bendDeduction`, cross-checked vs
   `totalLengthExpr`; the generator throws on disagreement — surface it in the UI, never commit an invalid shape.
4. **`.rcfg` forward-compat (NORMATIVE):** all new fields additive; a v1.0.2 file loads via legacy defaults
   (one level, no overrides, single support, unspliced, uniform spacing). Migrations live at the `rcfgToDoc`
   chokepoint (`engine/rcfgDoc.ts`), idempotent.
5. **a11y parity:** every new pointer action has a keyboard/numeric equivalent.
6. **Golden discipline:** when a render/exporter golden legitimately changes (G1 bends bars on the elevation;
   G6 adds coupe dims), **re-baseline it deliberately and say so in the §9 handoff**; the **BBS/cutLength
   goldens stay byte-identical** (rendering does not change cut lengths).
7. **Performance:** solve + redraw < 16 ms on the heavy cases (`tests/perf_heavy.spec.ts` — extend it).

## Phase 1 — G1: True bar geometry rendering ([REF-SYS-960], spec §1)

**Objective.** Make `placeBars` render every bar's real bent `centerline3D` (longitudinal bars follow their
shape; continuous coils placed once; stair bars follow the waist+landing), so façonnage/hooks/relevés/spirals/
stairs appear in 3D + coupe + PDF/DXF, with endpoints exiting the concrete. **Foundation for almost everything.**

**Depends on:** baseline green.

**Steps:**
1. **Longitudinal placement** (`section/place.ts`, the `for (bp of bars)` loop). Replace the straight 2-point
   line with the group's `g.shape.centerline3D` mapped onto the member frame at the bar's `(u,v)`:
   **convention — `worldX = u + localY·0` … precisely: `worldX = u`, `worldY = axisStart + localX`,
   `worldZ = v + localY`** where `(localX, localY)` are the shape centreline's local plane coords (the generator
   emits a 2D `centerline3D` with z≈0). `axisStart = 0` for a full-length bar. **This is byte-identical for a
   straight `DROITE`** (localY≡0 → worldZ≡v, localX 0..L → worldY 0..L). A hooked/cranked/relevé bar now bends in
   the **depth plane** (its return goes ±Z = the section `v` direction). Keep `barIndex` on the PlacedBar.
   *(Add an optional per-bar `axisStart`/bend-plane hook now if trivial — G2 will use `axisStart` for
   unique-length bars; otherwise default 0.)*
2. **Continuous-coil branch** (the transverse loop in `placeBars`). Before the per-station `placeLoop` loop, test
   `isContinuousCoil(g.shape)` (a helper that checks `"coilLength" in g.shape`, mirror `bbs.ts`). If true, emit
   **ONE** PlacedBar whose points are the helix `centerline3D` oriented along the member axis — the helix's axis
   (local +v per D-P4a-6) → world **+Y over 0..length**, its u–w circle → section X–Z (`u→X, w→Z`); do **not**
   call `placeLoop`, do **not** instance per station. Else keep the current per-station `placeLoop(…, anchor)`.
3. **Stair bars** render via step 1 automatically (the `MARCHE_PALIER` centreline now placed) — confirm the
   `solveStair` main bars carry the bent shape and that step-1's mapping orients flight→axis, landing bend→depth.
4. **Perf:** extend `tests/perf_heavy.spec.ts` with a dense circular column (helix) + a heavy beam (many bent
   bars) → still < 16 ms.

**Tests:** `tests/true_geometry.spec.ts` (a hooked column long bar's placed points bend at the end, NOT a
straight line; a straight bar is byte-identical to before), `tests/coil_placement.spec.ts` (a spiral column emits
ONE coil bar spanning 0..length, not N flattened loops), `tests/stair_bars.spec.ts` (stair main bar follows the
waist+landing). **Re-baseline:** `dxf1_golden`, any `elevation_fiche` expectations that assumed straight chapeaux
(the reference beam's `CHAPEAU` bars now show their returns) — update the expected values and note it.

**DoD:** bent geometry renders everywhere (3D/coupe/PDF/DXF), spirals are one coil, stairs read as bent bars;
straight-bar elements byte-identical except the intentionally re-baselined render goldens; BBS/cutLength goldens
unchanged; perf < 16 ms. + template.

**Risks:** the local→world mapping is the crux — get the depth-plane convention right (return bends go into `v`).
Spiral orientation (axis = local v) must match `bespoke/helix.ts`'s frame; read it before coding.

## Phase 2 — G6: Stirrup cadence continuity + coupe dimensions ([REF-SYS-757b/925c], spec §6)

**Objective.** (a) Make multi-region stirrup stations **continue the cadence across a boundary** (no illogical
stub); (b) render the coupe's **section dims + cover on both faces** (PDF) and **region-length dims** on the
elevation.

**Depends on:** P1 (shares `place.ts`).

**Steps:**
1. **Cadence** (`section/place.ts` `regionStations`). Keep the single-full-length-region delegation to
   `transverseStations` (byte-identical). For multi-region, **carry a running station `y` across boundaries**:
   start `y = margin`; for region 0 step by `region0.spacing` while `y ≤ region0.to`; **for each next region,
   keep stepping from the carried `y` but switch the step to that region's spacing once `y ≥ region.from`** (do
   NOT reset to `region.from`); last region stops at `length − margin`. Update `regionStationCounts` to count
   each station into its containing region `[from, to)` (last inclusive). Update `tests/transverse_regions.spec`
   expected stations/counts; `fiche` callouts (region midpoints) are unaffected.
2. **Coupe dims (PDF)** (`exporters/pdf.ts` `drawCoupe`). Render `view.dimensions` (currently ignored): for each
   `CoupeDimension`, draw a dimension line + label (mirror `dxf.ts coupeToDxf`). Ensure `sectionAt` emits
   **WIDTH + HEIGHT + a COVER dimension on each face** — extend `section/sectionAt.ts` to populate `dimensions`
   (it's templated today): width = section b/D, height = h/D, cover = the inset to the nearest bar per face.
3. **Elevation region dims** (`exporters/fiche.ts` `buildElevationFiche`). Add `FicheDim` entries for each
   stirrup **region length** (a dimension line under the existing tie callouts), in addition to the overall
   length. Render them in both `pdf.drawElevation` + `dxf.elevationToDxf` (they already iterate `fiche.dims`).

**Tests:** `tests/region_cadence.spec.ts` (no short stub at a boundary; continuity), `tests/coupe_dims.spec.ts`
(PDF coupe contains WIDTH/HEIGHT + per-face COVER; sectionAt emits them). Update `transverse_regions` + any fiche
golden.

**DoD:** boundary cadence continuous; coupe shows section dims + cover both faces; elevation shows region-length
dims; uniform sets byte-identical. + template.

## Phase 3 — G5: Cross-tie / épingle unification + anchoring ([REF-SYS-756b], spec §5)

**Objective.** Zero épingles by default (already true for fresh docs — verify), **all épingles anchored** to
their bars with **visible hooks** (3D + coupe + PDF/DXF), and the **legacy centred supplement-épingle path
removed** — one cross-tie model.

**Depends on:** P1 (anchored loops + hooks now render).

**Steps:**
1. **Remove the centred fallback for épingles** (`section/place.ts`, the final "supplements (presence only,
   centred)" loop). Generalise the F2 `anchor` to supplements: a supplement that binds a bar pair carries an
   `anchor{u,v,angleDeg}` (compute it in the adapter via `resolveBarPairPlacement`, like `resolveCrossTies`), and
   `placeLoop` places it at the anchor (already supported). For a supplement with no anchor (e.g. skin bars),
   keep a centred placement but **only for non-épingle roles**.
2. **Adapter** (`engine/solveDoc.ts` `resolveDocSupplements`). For an épingle-role supplement (manifest
   `SUPP_EPINGLE_CROSSTIE`), set `anchor` from `resolveBarPairPlacement(baseBars, i, j)` (+ pass
   `params.hook_angle` from the element's `crossTieHookAngle`). Better: **migrate épingle supplements into the
   `crossTies` list** at the `rcfgToDoc` chokepoint (`engine/crossTies.ts migrateDoc` + `rcfgDoc.ts`) so there is
   ONE model; drop the épingle entry from `supplements`. Keep the rebind-WARN flow.
3. **Default check.** Confirm `defaultColumnDoc`/`defaultBeamDoc` ship `crossTies: []` + `supplements: []` (they
   do) → no phantom épingle. Confirm the default scheme doesn't auto-seed one.
4. **Hook visibility.** With P1, the épingle's `centerline3D` (incl. its `hook_angle` hooks) renders in 3D; the
   coupe must show the **true bent hook** — see P7/G7 note (sectionAt should depict the épingle's in-plane hook,
   not just a circle). Wire the épingle `hook_angle` from `crossTieHookAngle` through `resolveCrossTies` (already
   done) and verify it reaches `centerline3D`.

**Tests:** `tests/epingle_anchored.spec.ts` (an épingle's placed centre = the bar-pair midpoint, NOT the section
centre; its points include the hook bend; the hook angle reflects `crossTieHookAngle`); update
`tie_legs_geometry`/`confinement_required` if needed; assert NO centred épingle remains for a default doc.

**DoD:** no default épingle; every épingle anchored with a visible hook in 3D/coupe/PDF/DXF; legacy
supplement-épingles migrate to cross-ties; no centred épingle anywhere. + template.

## Phase 4 — G2: Addressable bars, section levels & façonnage editor (L2) ([REF-DATA/UI/SYS-530], spec §2)

**Objective.** Move from "group of N identical bars" to **individually addressable bars** (per-bar shape/length/
replace), **independent extra bars**, and **section levels** (depth layers incl. the intermediate U-bar level),
with placement by picker **and** numeric. **The largest phase — stage it a→d.**

**Depends on:** P1 (geometry renders overrides), P3 (clean épingle model).

**Steps:**
- **G2a — Section levels.** Extend the doc + layout to place bars at named **levels** (a settable `v` band, or a
  `layerIndex`). `engine/document.ts`: add a `levels` declaration to Column/Beam docs (default = today's faces →
  legacy byte-identical). `layout/rect.ts`: accept explicit level `v`s / extra positions (extend the descriptor;
  the engine stays generic). The U-bar level for beams = an intermediate `v` just under TOP.
- **G2b — Per-bar overrides.** `engine/document.ts`: a group gains `barOverrides?: {index, shapeId?, faconnage?,
  length?, axialPos?, diameter?, removed?}[]` (all optional; absent → grouped behaviour). `engine/solveDoc.ts`:
  when overrides exist, **expand the group into per-bar `ElementLongInput`s** (one grouped input otherwise →
  goldens safe); each overridden bar gets its own `shape`/`params`/`hooks`/`diameter`; `length`+`axialPos` feed
  P1's `axisStart` + a shorter run. The engine already accepts arbitrary shapes/params — **no core branch**.
- **G2c — Independent extra bars.** `engine/document.ts`: `extraBars?: AddressableBar[]` (level, section
  position, shape, length, axialPos, Ø) on the doc. `solveDoc`: append them as their own longitudinal inputs.
- **G2d — Façonnage editor.** `ui/FaconnageEditor.tsx`: target a **specific bar** (or the group); keep the live
  sketch + cutLength guard (D-P1-1). With P1 the choice now **flows to 3D/coupe/BBS/DXF/PDF** (closes the v1.0.2
  gap where only the sketch updated). Wire bar selection via the **F7 `SectionPicker`** (level-aware) + numeric
  (face/level + offset). Position model = **picker AND numeric** (a11y parity).
- **BBS** (`exporters/bbs.ts`): distinct bars still merge; a uniquely-shaped/uniquely-long bar becomes its own
  line (the merge key already includes shape+Ø+dims, so this works once overrides feed real shapes).

**Tests:** `tests/section_levels.spec.ts`, `tests/bar_overrides.spec.ts` (override one bar's shape/length →
that bar differs, the rest unchanged; legacy doc byte-identical), `tests/independent_bars.spec.ts`,
`apps/web/.../faconnage_editor.spec.tsx` (extend: per-bar target + flows to the solved geometry), `.rcfg`
round-trip of overrides/levels/extraBars + legacy-default migration.

**DoD:** a user can shape one bar (one/both ends), add an independent bar, replace/remove a bar, give a bar a
unique length+axial position, and assign bars to ≥3 levels — visible in 3D/coupe/PDF/DXF + schedule; legacy
files load unchanged. + template.

**Risks:** keep the **grouped fast path byte-identical** when no overrides/levels/extraBars (gate the expansion
on their presence) to protect every existing golden. Effective-depth `d` must read the real per-bar/per-level
centroid (the layout already computes it — feed the new levels in).

## Phase 5 — G3: Beam two-support model + relevés ([REF-DATA/SYS-260], spec §3)

**Objective.** Replace the single `supportZone` with **two independent supports V1/V2** (asymmetric chapeaux +
anchorage + width), make **relevés** a first-class zone, and **auto-seed editable** stirrup regions from supports.

**Depends on:** P4 (relevés + per-support chapeaux are addressable, unique-length, shaped bars; G2 gives the
machinery), P2 (stirrup regions).

**Steps:**
1. **Doc model** (`engine/document.ts` `BeamDoc`). Replace `chapeau{supportZone}` with `supports: { left:
   SupportZone; right: SupportZone }`, `SupportZone = { chapeau:{enabled,diameter,nTop,asReq,length}, anchorage,
   width }`. Add `releves?: ReleveZone[]` (count, Ø, bend stations near a support — a `RELEVE`-shaped bottom bar,
   rides G2). Keep legacy migration: a v1.0.2 `chapeau{supportZone}` → symmetric `left=right`, no relevé.
2. **Adapter** (`engine/solveDoc.ts beamInput`). Build **per-support** chapeau inputs (each its own `RELEVE`/

## Phase 6 — G4: Lap splices / couplers ([REF-SYS-770], spec §4)

**Objective.** Full lap/coupler scheduling: splice points, lap length from code, stagger, couplers; segments +
couplers in schedule + drawing.

**Depends on:** P4 (a spliced bar is an addressable bar with segments).

**Steps:**
0. **Confirm the lap-length function** in `packages/core/src/types/codepack.ts` + `packages/codepacks/src/bael`
   (likely `code.l0(...)` or a lap relation off `code.lbd`); use it — do not invent a new constant.
1. **Pure core helper** `packages/core/src/geometry/splice.ts` `spliceBar(length|centreline, splices[], code) →
   segments[]`: each segment's `cutLength` includes the lap overlap `l_r = code.l0(...)`; a coupler segment has
   zero overlap + a coupler count. **Preserve the cutLength invariant** (segments sum to the run + Σ overlaps).
   Export from `index.ts`.
2. **Doc model** (`engine/document.ts`): a longitudinal group/bar gains `splices?: {at:number, kind:"lap"|
   "coupler"}[]` (manual) + an `autoSplice?` flag (auto-split when the run > stock length — default 12 m, reuse
   the BBS `nestCuts` stock). Additive; absent → unspliced.
3. **Schedule** (`exporters/bbs.ts`): a spliced bar emits its **segments** (each a scheduled line incl. overlap)
   + a **coupler count**. **Stagger predicate** (`validation/predicates.ts` + `seismic.ts`): adjacent bars'
   splices offset by a code fraction → WARN if coincident in a critical zone (reuse `lap_in_critical_zone`).
4. **Drawing** (P7 consumes): a **splice symbol + lap length** at each splice.

**Tests:** `tests/lap_splice.spec.ts` (segments incl. overlap, sum correct, cutLength invariant), `tests/
coupler.spec.ts`, `tests/lap_stagger.spec.ts` (coincident-lap-in-critical-zone WARNs). Legacy bars unspliced.

**DoD:** bars splice (lap/coupler) with code lap length + stagger; segments + couplers scheduled + drawn; legacy
unspliced. + template.

## Phase 7 — G7: Shop-drawing PDF/DXF ([REF-SYS-930], spec §7)

**Objective.** Turn the export into a real shop drawing: per-bar leader lines (`mark · nØd · l=`), per-element
sequential marks, coupe markers, stirrup-zone notation, support labels/dims, and a per-distinct-shape bending
table — for PDF + DXF, built once.

**Depends on:** P2 (coupe/elevation dims), P5 (supports), P6 (splice marks), P4 (bar marks).

**Steps:**
1. **Annotation model** `packages/exporters/src/shopDrawing.ts` `shopDrawing(result, opts) → {leaders, marks,
   coupeMarkers, stirrupZones, supportLabels, bendingTable}` built over `buildElevationFiche` + `computeBBS` +
   `sectionAt` (pure; shared by PDF + DXF so they agree). A **leader-line placement** helper (basic anti-overlap).
2. **Per-element sequential marks** (repères 1,2,3…) assigned by the BBS ordering, separate from the project
   namespaced marks (v1.0.1 `markPrefix` stays for the project schedule). Each distinct bar run gets a numbered
   leader `① 3Ø12 l=1.50`.
3. **Coupe markers** A-A/B-B on the elevation (extend `cuttingLineFiche`); **stirrup-zone notation** `count ×
   spacing` per region (from P2/P6 region stations); **support labels + widths + anchorage** (from P5).
4. **Bending table** — one row per **distinct shape**: mark · shape sketch (from the `fiche` legs/bends/hooks) ·
   Ø · cut length · **count per element** · **total = count × element quantity**. Render in `pdf.ts`
   (new table, beside/under `drawBbsTable`) + the DXF.
5. Wire into `buildPdf`/`buildProjectPdf`/`buildDxf1`/`buildDxfCoupes`.

**Tests:** `tests/shop_drawing.spec.ts` (leaders with mark·nØd·l, sequential marks, coupe markers, stirrup-zone
notation, support labels), `tests/bending_table.spec.ts` (one row per distinct shape, per-element + ×quantity
total). Deterministic with a fixed date.

**DoD:** PDF/DXF show the full shop-drawing annotation set + bending table; deterministic. + template.
