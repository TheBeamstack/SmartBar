# RebarConfig (SmartBar) v1.0.6 — Specification: the drawing-board UI

### Track U1 workspace shell (3D-primary + editable 2D docks) · U2 one unified section canvas + tool modes · U3 contextual inspector · U4 tool palette & gestures · U5 editable elevation · U6 control-type pass

> **What this release is.** v1.0.5 makes SmartBar a bar-level detailer *in the engine* — any bar, any shape,
> any position, on all 8 elements — but surfaces it through the **existing form UI**. v1.0.6 changes **how a
> user reaches and edits** that capability: it moves the app from *"edit a form, watch the drawing"* to
> *"work on the drawing, the form follows."* No engine/validation/schedule changes — this is a **presentation-
> and-interaction** release over the v1.0.5 model, exactly the disposable layer the architecture was built to
> keep replaceable.
>
> **Hard dependency.** v1.0.6 requires the **v1.0.5 placed-bar model** (`PlacedBar` = single / row / layer /
> bundle / skin, per-bar curtailment, all-8-element placement). It adds no new steel *kinds* — it makes the
> ones v1.0.5 introduced directly manipulable.
>
> **Provenance.** Synthesis of the UI/interaction review + owner design decisions taken 2026-07-09 (§8).
> **Companion:** `v1.0.6_owner_tasks.md` (owner GPU/visual acceptance passes — the headless gate can't see WebGL).

---

## 0. Goal, scope & invariants

### 0.1 The goal
Today the drawing is **output-only**: every parameter is a number typed into a long left-hand form (the
`Sidebar`), and the 3D + coupe merely *update*. The only direct-manipulation affordance is the coupe
drag-handle. For a detailing firm this is backwards — detailers work **on** the drawing (select a bar, drag
its end, drop a new bar where it's needed). Eight findings drove this (U1–U8 in the UI review); v1.0.6 answers
them while **keeping every number as a precision/a11y backstop.**

### 0.2 Scope
**IN:**
- **U1** — a workspace shell where the **live 3D stays primary/always-on** and **editable 2D section +
  elevation docks** flank it (owner decision).
- **U2** — collapse the **three separate section pickers** (Bar-by-bar / Cross-ties / Supplements) into **one
  persistent section canvas** whose active tool decides what a click means.
- **U3** — a **contextual inspector** driven by selection; **the current tabbed form is kept as an "advanced"
  fallback** (owner decision).
- **U4** — a **modal tool + shape/row palette** (owner decision): select / add-bar / add-row / link / measure,
  with a palette of shapes and row/bundle/layer/skin types to drop on the canvas.
- **U5** — an **editable elevation**: drag bar ends (curtailment), lap/coupler points, bend-up points, and
  stirrup-zone boundaries — wired to the v1.0.5 per-bar station model.
- **U6** — a **control-type pass**: steppers for counts, plain numbers for design inputs, sliders kept only
  where a value is genuinely tuned against live 3D.

**OUT (explicit):**
- **Any engine / validation / schedule / `.rcfg` change** — all of that is v1.0.5. If a UI need exposes an
  engine gap, it is logged for a point release, not built here.
- New element types / codes / backend (later).

### 0.3 Hard invariants (carried + UI-specific)
1. **Engine purity** — v1.0.6 touches **only `apps/web`** (`ui/`, `viewport/`, `store/`). No `packages/core`
   change. Enforced by `check:purity`.
2. **Live re-solve stays under 16 ms** — every gesture commits through the store's synchronous re-solve
   (`useStore.withDoc`); drag uses the existing `dragMode` render-degradation, not a solve skip.
3. **a11y parity (NORMATIVE).** Every direct-manipulation gesture has a **numeric + keyboard twin**: a drag
   exposes a live typed coordinate; every canvas keeps its labelled button-list (the existing `SectionPicker`
   a11y list pattern). Nothing becomes mouse-only. Verified per feature.
4. **Selection is one system.** Unify today's two selection channels (`selectedBars` for bars,
   `selectedGroupIds` for alert rows) into one addressable selection that drives the inspector + the 3D/2D
   highlight consistently.
5. **Determinism of state** — view/tool/inspector state is **session-only, NOT in `.rcfg`** (like
   `projection`/`rollRad`/`navMode` today). The document is unchanged by looking at it.
6. **Every phase ends green** — `npm run check` + RTL/store tests; GPU-only behaviour verified by the owner
   pass (headless can't drive WebGL), consistent with prior UI phases.

### 0.4 Cross-cutting quality bar
- Pure helpers (hit-testing, coordinate mapping, snap, tool-state reducers) are **headless-unit-tested**; the
  GPU widgets are owner-verified. This mirrors v1.0.1–v1.0.3 UI phasing (`cameraState`, `coupeHandle` pure +
  tested; the drei widget owner-verified).
- No feature regresses the sub-16 ms budget or the a11y parity.

# Track U1 — The workspace shell (3D-primary + editable 2D docks)  `[REF-UI-830]`

**Owner decision: 3D stays primary/always-on; section + elevation are editable docks.**

**Requirement.** Restructure the `App` shell (`App.tsx`: navbar / left `Sidebar` / center `Viewport` +
bottom `BottomPanel` / right `RightColumn`) into a workspace where:
- the **live 3D `Viewport` remains the central, always-on surface** (preserving the current strength — live
  cage + coupe handle);
- a **section dock** and an **elevation dock** are first-class, **editable** 2D panels docked around the 3D
  (not buried inside the scheme form); each is resizable/collapsible;
- the **right column** (Verification / Project / BBS) is retained;
- the **inspector** (U3) occupies the left region the form used to own.

The bottom `Coupes` dock is subsumed by the section dock (the coupe *is* the editable section). View/dock
layout is session-only.

**Tests.** `workspace_shell.spec.tsx` — the three surfaces mount; docks resize/collapse; 3D stays mounted;
layout state is not persisted to `.rcfg`.

# Track U2 — One unified section canvas + tool modes  `[REF-UI-555]`

**Finding U2.** The `SectionPicker` is embedded **three times** (in `AddressableBars`, `CrossTieEditor`,
`SupplementsPanel`), each with a local pending-pick (`useBarLink`) and a different meaning.

**Requirement.**
- **One persistent section canvas** in the section dock, rendering the element's real cross-section (bars as
  labelled face-coloured dots at their `(u,v)`, the concrete envelope, cover) from `result` — the existing
  `SectionPicker` SVG generalised.
- Its behaviour is governed by the **active tool** (U4): *select* a bar → inspector; *add-bar/row* → drop at
  the clicked level; *link* → connect two bars into a cross-tie / bind a supplement. Cross-ties and
  supplements become **gestures on this one canvas**, not three separate embedded copies.
- Retire the three embedded pickers; `AddressableBars` / `CrossTieEditor` / `SupplementsPanel` become
  *inspector modes*, not owners of a section widget.
- Keep the **labelled button-list a11y twin** for every pick/link (invariant §0.3.3).

**Tests.** `section_canvas.spec.tsx` — one canvas; tool-mode routing (select/add/link) hits the right store
action; cross-tie + supplement flows work through it; a11y list parity retained.

# Track U3 — Contextual inspector (form kept as advanced fallback)  `[REF-UI-820]`

**Owner decision: inspector added; the tabbed form stays reachable as an "advanced" fallback.**

**Requirement.**
- A **selection-driven inspector**: select a bar / row / bundle / layer / cross-tie (via the section canvas,
  the elevation, or the 3D — all feed the unified selection, §0.3.4) → the inspector shows **only that
  object's properties** (Ø, shape via the reused `FaconnageEditor`, hooks, start/end stations, splices,
  remove; for a row: count/spacing/level; for a bundle: n).
- **Element-level setup** (geometry b/h/L, cover, material, code pack, seismic) lives in a **compact
  always-visible header/strip** so it's no longer a separate tab-flip away from the drawing (answers U6-IA).
- **The current tabbed form (`Sidebar`) is retained behind an "Avancé / Advanced" toggle** — a complete
  fallback for bulk edits and power users, and a safety net during the transition. Both paths mutate the same
  store; neither is authoritative.
- The sticky three-tier **`ZoneReadout`** is preserved (it already works well).

**Tests.** `inspector.spec.tsx` — selecting each object type shows the right fields; edits round-trip to the
store == the form path; the advanced form remains reachable and consistent; readout preserved.

# Track U4 — Tool palette & gestures  `[REF-UI-560]`

**Owner decision: modal tools + a shape/row palette.**

**Requirement.**
- A **toolbar** sets the active mode: **Select · Add bar · Add row · Add layer · Add bundle · Link (cross-tie)
  · Measure**. The active tool is shown (aria-pressed) and has a keyboard shortcut; `Esc` returns to Select.
- A **palette** holds the shape archetypes (the 16 façonnage shapes) and the row/bundle/layer/skin types; the
  user picks a palette item, then places it on the section (click at a level) or the elevation.
- **Placement snaps** to the cover envelope + a layer grid (grid density from element geometry); a live
  coordinate readout shows the snapped `(u,v)` / station and is **typable** (a11y/precision backstop).
- **Discoverability (answers U8):** "add any bar" is now a visible tool + palette, not a buried numeric
  sub-panel. The tool + palette work on **all 8 elements** (the v1.0.5 model supports it).

**Tests.** `tools.spec.tsx` — tool switching + shortcuts + Esc; palette selection; a place gesture creates the
right `PlacedBar` in the store with snapped coords; the typed-coordinate twin sets the same value.

# Track U5 — Editable elevation (curtailment · laps · zones · bend-up)  `[REF-UI-811]`

**Finding U7.** The longitudinal elevation — where a detailer spends most time — is not editable; curtailment,
laps, bend-up points and stirrup zones are numeric-only (`RegionEditor` boundary drag was explicitly deferred).

**Requirement.** Make the elevation dock a canvas over the v1.0.5 model:
- **Drag a bar end** → sets its **curtailment station** (v1.0.5 P2); the drawing + BBS cut length update live.
- **Drag a "runs-through" handle** at a support → toggles/extends anchorage into the support (v1.0.5 P2).
- **Drop a lap/coupler** by pointing → sets a splice station (v1.0.5 Track S); staggered laps show.
- **Grab a bend-up point** → sets a relevé's bend station + up-leg (replaces the hardcoded relevé geometry
  the v1.0.5 model now exposes).
- **Drag stirrup-zone boundaries** → edits the `TransverseRegion` set; the numeric `RegionEditor` table stays
  as the a11y/precision twin.
- Every gesture has a live typed value; the numeric controls remain as the backstop, not the primary path.

**Tests.** `elevation.spec.tsx` (pure hit-test/coord/snap helpers headless; drag behaviour owner-GPU-verified) —
dragging an end changes the store curtailment station + BBS cut; lap-drop sets a splice; zone-boundary drag
edits regions == the table; numeric twins agree.

# Track U6 — Control-type pass  `[REF-UI-widgets]`

**Finding U4.** `NumberField` (slider + number box) is used for everything — counts, As,req, angles, a 0–1
fraction — where a slider often makes no sense and even trips `dragMode` needlessly.

**Requirement.** Right widget per parameter (per the UI review's control inventory):
- **Counts** (bars per face, row count, bundle n) → **stepper** (− N +).
- **Design inputs** (As,req) → **plain number** with units (cm² ↔ mm²), no slider, no `dragMode`.
- **Dimensions genuinely tuned against live 3D** (b, h, L, cover) → keep the slider+number (and add the
  on-drawing drag from U1/U5), because live sweep against the 3D is the one place a slider earns its place.
- **Diameter** → keep the existing `select` (already correct).
- Remove `dragMode` from non-geometry sliders.

**Tests.** `controls.spec.tsx` — counts render a stepper; As,req is a number and does not toggle `dragMode`;
dimension sliders keep live-tune behaviour; diameter stays a select.

## 7. Build sequencing (macro-phases; each ends green per §0.4)

| Phase | Delivers | Depends on | Owner GPU pass |
|---|---|---|---|
| **N1 — Controls** | U6 control-type pass | — | light |
| **N2 — Section canvas** | U2 unified section + tool routing (Select/Link first) | v1.0.5 model | yes |
| **N3 — Inspector** | U3 inspector + advanced-form fallback + unified selection | N2 | yes |
| **N4 — Shell** | U1 3D-primary shell with editable 2D docks | N2, N3 | yes |
| **N5 — Placement tools** | U4 tool palette + place-by-pointing (all 8 elements) | N2–N4 | yes |
| **N6 — Elevation** | U5 editable elevation (curtailment/laps/zones/bend-up) | N5 | yes (largest) |

Ordering rationale: N1 is cheap polish; N2–N3 re-wire the **existing** selection + section into a workspace
with no new engine need; N4 composes the shell; N5–N6 are the larger direct-manipulation builds. Each phase
ships value alone.

## 9. Definition of "complete" for v1.0.6
A detailer **works on the drawing**: one persistent section canvas + an editable elevation around the always-on
3D; a tool palette places any shape/row/bundle/layer on any of the 8 elements; selecting anything opens a
contextual inspector; bar ends, laps, bend-ups and stirrup zones are dragged directly — and **every gesture
still has a number and a keyboard path**. The engine, validation, schedule and file format are exactly the
v1.0.5 ones; v1.0.6 changed only how a human reaches them. The advanced form remains as a complete fallback.
