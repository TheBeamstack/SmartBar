# RebarConfig v1.0.2 — Implementation Plan (7 feature-phases)

**Companion to:** `v1.0.2-Spec.md` (DRAFT, 2026-06-27).
**Audience:** an implementing agent starting a fresh session. Each phase is self-contained — objective,
prerequisites, exact file targets, steps, tests, and a binary Definition of Done. Read the *Global Context*
once, then execute the phases **in order** (the order is dependency-driven: F7's picker underpins F2).
**Status:** validated against `v1.0.2-Spec.md` (see §V — Validation Matrix). The seven phases map 1:1 onto the
spec's seven features (F1–F7); the *execution* order is the spec §8 build order **F7 → F2 → F3 → F4 → F5 → F6
→ F1** (a UI-only/foundation-first sequence).

> **Golden rule (spec §0.1 / v1.0.2 §0):** everything structural stays **data** (manifests + registered
> functions). F2 (cross-ties) and F5 (regions) add engine capability but **only through existing seams** — the
> placement-rule seam and the transverse-segment seam — with **no `if (elementType === …)`** in `packages/core`.

## Global Context (read once)

### What v1.0.2 is
A **horizontal, no-backend** increment on top of the shipped v1.0.1 build. Seven targeted changes: three fix
defects (F2 cross-ties draw centred/unbound; F3 readouts scroll away; F7 bar binding is unusable) and four add
capability (F1 in-plane roll; F4 focus-friendly layout; F5 per-region cadre spacing; F6 user façonnage). See
`v1.0.2-Spec.md` for the full feature text and the **[OWNER ✓]** decisions.

### Stack & layout (unchanged from v1.0)
Monorepo: `packages/core` (pure engine), `packages/codepacks` (BAEL/EC2/RPS), `packages/exporters` (BBS/DXF/
PDF/.rcfg + `fiche.ts`), `apps/web` (React 18 + Vite + Zustand + R3F/three), `tests/`. Node 20 / npm 10.
Run: `cd apps/web && npm run dev` (port 5180). Gate: `npm run check` (+ `npm run coverage`, `npm run build:web`).

### Non-negotiable invariants (verify every phase — v1.0.2 §0)
1. **Engine purity:** nothing new in `packages/core` imports React/three/`window`/`document`.
2. **Determinism:** pure solver, byte-identical output; existing golden tests stay green.
3. **Data-driven / no element branching:** no new `if (elementType===…)` / `if (codePack===…)` in core.
4. **`.rcfg` forward-compat (NORMATIVE):** F2 cross-tie lists, F5 region lists, F6 `shapeId`/`shapeParams`/
   `hooks` are **additive** fields, preserved on round-trip; a v1.0.1 file (without them) loads via legacy
   defaults.
5. **`cutLength` invariant (D-P1-1):** every user-shaped bar keeps `cutLength = Σ legs + Σ hookExt −
   Σ bendDeduction`, cross-checked vs `totalLengthExpr`.
6. **a11y parity:** every new pointer action (roll-ring, 2D bar click, region/boundary drag, façonnage sketch)
   has a keyboard/numeric equivalent.
7. **Performance:** solve+redraw < 16 ms on edit; the existing drag-degradation path is untouched.

### Definition-of-Done template (applies to every phase)
- [ ] All steps implemented at the stated file paths.
- [ ] Phase tests green; `npm run check` end-to-end green (purity → manifests → typecheck → web typecheck →
      tests); `npm run build:web` green; `npm run coverage` ≥ 90% core (F2/F5/F6 add core lines → keep it).
- [ ] No new `if (elementType===…)` / `if (codePack===…)` in `packages/core`.
- [ ] `.rcfg` forward-compat preserved (additive fields + legacy-default migration tested).
- [ ] `current_state.md` updated (§1 row + a §9 handoff entry + any D-V102-* decision).

### Engineering sign-off gates
**Unchanged.** v1.0.2 adds **no new gate**. F2's "Auto (code)" cross-tie rule and F5's seismic reconciliation
ride the **existing provisional RPS overlay** (gate **G-RPS**); they ship flagged `_provisional` like their
overlay. F1/F3/F4/F7 are pure presentation/interaction (no structural math).

### What still needs the owner's GPU/eye (not headless-verifiable)
The F1 roll-ring feel, the F7 3D-bar click + the live 2D section picker, the F5 boundary-drag, and the F6 live
sketch interactions are verified on the owner's Windows GPU via `vite dev`. Their **pure logic** (roll vector,
bar-label map, region stations, shape generation, cutLength) is headless-tested in every phase.

## Phase 1 — F7: 2D section picker + usable bar-binding model (spec §7, [REF-UI-555]/[REF-SYS-555])

**Objective.** Replace the unusable raw-index binding with a **live 2D cross-section picker** (numbered,
face-coloured bar dots; click two to link) that drives both supplements and (next phase) cross-ties, synced
with 3D highlighting. **Foundation for F2.**

**Depends on:** v1.0.1 (the binding model — `nearestBarIndex`, `resolveBarPairPlacement`, indexed bindings —
already exists; this is the missing UI + 3D pickability).

**Steps:**
1. **`apps/web/src/engine/barLabels.ts`** (pure) — `barLabel(bar, allBars) → "T1"|"B2"|"L1"|"R3"|…` (face-
   relative, deterministic; §9 owner item 7) and `labeledBars(result) → {index,label,u,v,faceTag}[]`.
2. **`apps/web/src/ui/SectionPicker.tsx`** — SVG cross-section from `result.bars` positions + `faceTag`s; each
   bar a clickable, labelled dot; first click selects, second click links (calls the host's `onLink(i,j)`);
   selected bars push `selectGroups`/a new `selectedBars` so the 3D highlights them.
3. **3D pickability** — in `viewport/Rebar.tsx`/`Viewport.tsx`, make longitudinal bar meshes raycast-pickable
   → `nearestBarIndex` → same selection state (pointer addition; the picker list is the a11y fallback).
4. **Rewire `SupplementsPanel.tsx`** onto the picker (drop the `bar1/bar2` number inputs; keep a labelled
   `<select>` fallback). Bindings still store **stable indices** (unchanged `.rcfg`).
5. Store: `selectedBars: number[]` + a small "linking" interaction state; reuse existing `selectGroups`.

**Files:** `engine/barLabels.ts` (new), `ui/SectionPicker.tsx` (new), `ui/SupplementsPanel.tsx`,
`viewport/Rebar.tsx`/`Viewport.tsx`, `store/useStore.ts`, `i18n/strings.ts`, `styles.css`.

**Tests:** `bar_labels.spec` (pure label map: faces, ordering, stability); `section_picker.spec` (RTL: N dots
with labels, click-link calls onLink with the right indices, selection state); existing `supplement_rebind`,
`binding_keyboard` stay green.

**DoD:** the section picker shows numbered face-coloured dots; clicking two links them (épingle/supplement);
selection syncs to 3D; supplements bind through it with a keyboard fallback; bindings persist as stable indices
and survive a layout edit (re-solve + rebind-WARN unchanged). + DoD template.

**Risks:** keep bindings index-based (never coordinates) so a layout change re-solves; don't regress the
keyboard parity tests.

## Phase 2 — F2: column cross-ties rebuilt on real bar engagement (spec §2, [REF-SYS-756]/[REF-UI-756]/[REF-DATA-756])

**Objective.** Remove the broken `nLegs` model; make a cross-tie a **bar-pair-bound épingle placed *between*
the two engaged bars**, configured via the F7 picker, with per-direction presets and an **Auto (code)** button;
fix the seismic engaged-bar count.

**Depends on:** Phase 1 (the picker).

**Steps:**
1. **Core — anchored transverse placement.** Extend the transverse-group / placement so a tie can carry an
   **anchor `(u,v)` + span** (reusing `resolveBarPairPlacement`'s output) and make **`placeBars` place the
   épingle loop at that anchor** instead of centring it (`placeLoop` gains an offset). Pure; used by 3D + coupe.
2. **Doc model (`document.ts`).** Replace `ColumnDoc.tie.nLegs` (and the beam stirrup's) with the perimeter
   cadre + a **`crossTies: { barA:number; barB:number; diameter?:number; hookAngle?:number }[]`** list bound to
   longitudinal bar indices. Migration: a legacy `nLegs=N` → `(N−2)/2` centred-pair cross-ties (or perimeter-
   only if `N≤2`).
3. **Adapter (`solveDoc.ts`).** Build one anchored transverse group per cross-tie (épingle between `barA`/
   `barB`); **recompute `Asw` leg count from the real cross-ties** (perimeter 2/dir + Σ crossing ties);
   **feed the true `longBarsEngaged`** into the seismic block (drop the hardcoded 4). Remove `crossTieZones`'s
   centred groups.
4. **UI (`Sidebar` column/beam controls).** Drop the "Brins" number; add a cross-tie list (picker-driven add/
   remove), **per-direction presets** ("every other bar top↔bottom / left↔right"), and an **Auto (code)**
   button that engages alternate bars via the active **RPS overlay** (user-overridable).
5. **`.rcfg`:** persist `crossTies`; forward-compat + migration tested.

**Files:** `packages/core/src/section/place.ts` (anchor), `apps/web/src/engine/{document,solveDoc}.ts`,
`ui/Sidebar.tsx` (+ a `CrossTieEditor`), `i18n/strings.ts`, `tests/`.

**Tests:** `crosstie_engagement.spec` — épingle centre = midpoint of the two engaged bars (NOT section centre);
Asw leg count = perimeter + cross-ties; seismic `longBarsEngaged` reflects the configured ties; "Auto" engages
alternate intermediate bars. `crosstie_migration.spec` — legacy `nLegs` file → equivalent cross-tie set,
`.rcfg` round-trips. Keep `leg_count_asw`, `tie_legs_geometry` (update), `confinement_required` green.

**DoD:** no "Brins" number; each cross-tie renders **between** its two bars in 3D/coupe/BBS with end hooks;
number = model = schedule; Auto works + is overridable; seismic engagement is real; legacy migrates. + template.

**Risks:** the `placeBars` anchor change must not move the perimeter cadre or any existing element; gate the
offset behind the presence of an anchor so non-anchored groups are byte-identical (protect the goldens).

## Phase 5 — F5: user-defined transverse regions (spec §5, [REF-SYS-757]/[REF-DATA-757])

**Objective.** A transverse group carries an **ordered region list** (`from→to + spacing`), so cadre spacing
varies along the length; 3D, coupe stations, BBS counts and the elevation callouts all reflect it; seismic
**tightens** within end regions rather than replacing them.

**Depends on:** Phase 2 (both touch the transverse model; do regions after the cross-tie refactor lands).

**Steps:**
1. **Core — region model (transverse-segment seam).** A transverse group gains `regions: { from:number;
   to:number; spacing:number }[]` (contiguous over 0..L; `[{0,L,s}]` == today). `transverseStations` emits
   stations region-by-region; `placeBars` instances loops per region; **BBS counts cadres per region**.
2. **Seismic reconciliation (`validation/seismic.ts`).** The overlay's critical-zone spacing **takes the min
   within the end regions** (does not replace the list); a user region looser than the code minimum in a
   critical zone → **WARN** (not silent). The "symmetric ends" quick-fill can seed from the critical-zone
   length.
3. **Exporter (`exporters/fiche.ts`).** Per-region spacing callouts (`Ø8 e=100` / `e=200`) + region boundaries
   on the elevation; BBS lists per-region counts.
4. **Doc/adapter.** Region list per transverse group (column/beam/spiral-pitch); migration: single spacing →
   one region. **UI:** a region table (add/remove from→to + spacing), a **symmetric-ends quick-fill**, and an
   optional boundary **drag** on the elevation (numeric is the a11y baseline).

**Files:** `packages/core/src/section/place.ts` (`transverseStations`/`placeBars`), `validation/seismic.ts`,
`packages/exporters/src/{bbs,fiche,dxf,pdf}.ts`, `apps/web/src/engine/{document,solveDoc}.ts`,
`ui/Sidebar.tsx` (+ a `RegionEditor`), `i18n/strings.ts`, `tests/`.

**Tests:** `transverse_regions.spec` — stations + BBS counts per region; contiguity enforced; seismic tightens
within end regions + WARNs on a sub-code region; legacy single-spacing → one region; `.rcfg` round-trips. Fiche
callout test (per-region label present). Keep `rps_segment_injection` green.

**DoD:** N regions with distinct spacings reflected in 3D, coupe stations, BBS counts, and elevation callouts;
contiguity UI-enforced; seismic tighten + sub-code WARN; legacy → one region. + template.

**Risks:** keep `[{0,L,s}]` byte-identical to today (protect goldens); reconcile with seismic by *min*, not
override, so the seismic suites don't regress.

## Phase 6 — F6: façonnage editor + shape catalog (spec §6, [REF-SYS-520]/[REF-UI-520]/[REF-DATA-520])

**Objective.** Let the user pick each longitudinal bar group's **shape** from a catalog, edit its **parameters**
and **end hooks**, with a live 2D façonnage sketch; the choice flows to the solve, 3D, coupe, BBS and DXF/PDF.

**Depends on:** none structural (engine already accepts any shape+params); best after F3/F4 so the UI has room.

**Steps:**
1. **New shape manifests (data).** `apps/web/manifests/shapes/`: **Z-bar**, **double-crank**, **stepped**
   (segment-grammar entries; register in the shape registry — no pipeline change). They pass the manifest-
   integrity gate (schema + expression-scope + `totalLengthExpr`).
2. **Doc model.** Each longitudinal group gains user-editable `shapeId` + `shapeParams: Record<string,number>`
   + `hooks: { start:HookKind; end:HookKind }` (today these are hardcoded/auto). `solveDoc` **passes them
   through** instead of computing them (keeps the engine generic).
3. **UI — façonnage editor (`ui/FaconnageEditor.tsx`).** Per group: a shape `<select>` from the catalog,
   parameter `NumberField`s seeded from geometry, a start/end hook control (none/90/135/180 + length), and a
   **live 2D SVG sketch** from `generateBarShape → fiche` showing legs/bends/hooks + the computed `cutLength`.
4. **Invariant guard.** Surface a clear error when custom params break the `cutLength`/`totalLengthExpr`
   cross-check or exceed the member; block the solve from a nonsense shape.
5. **BBS/exports.** Render the `fiche` sketch + coded dims in the BBS façonnage column; the DXF/PDF bar marks
   already use the real shape.
6. **`.rcfg`.** Persist `shapeId`/`shapeParams`/`hooks`; forward-compat; legacy file → v1.0.1 default per group.

**Files:** `apps/web/manifests/shapes/{zbar,double_crank,stepped}.json` (new), `apps/web/src/engine/
{document,solveDoc}.ts`, `ui/FaconnageEditor.tsx` (new) + `ui/Sidebar.tsx`, `packages/exporters/src/pdf.ts`
(BBS sketch) — optional, `i18n/strings.ts`, `tests/`.

**Tests:** `facade_shapes.spec` (the three new manifests generate valid centrelines + cutLength matching
`totalLengthExpr`; integrity gate passes); `faconnage_editor.spec` (RTL: pick shape, edit a param, hook control,
sketch renders, invalid param rejected); `.rcfg` round-trip with custom shape; legacy-default test.

**DoD:** every longitudinal group can choose a catalog shape + params + end hooks with a live sketch + cutLength;
new shapes valid; invalid params rejected; choice flows to 3D/coupe/BBS/DXF/PDF; legacy loads default. +
template. **Deferred (flagged):** lap-splice/coupler scheduling between elements (v1.0.2 §6.6).

**Risks:** the `cutLength` invariant (D-P1-1) is the trap — reuse the generator's existing cross-check; never
"simplify" cutLength to the polyline sum.

## Phase 7 — F1: in-plane view roll (spec §1, [REF-SYS-811]/[REF-UI-811])

**Objective.** Add the missing rotation around the view axis (roll within the screen plane), controlled by a
roll-ring + ↺/↻ buttons, re-levelled by Home/named views; session-only.

**Depends on:** none (camera/interaction-only).

**Steps:**
1. **Pure helper `viewport/cameraState.ts`** — `rollUpVector(viewDir, rollRad) → up` (headless-testable).
2. **Store** — `rollRad: number` (session state, **NOT** in `.rcfg`); set by ring/buttons; reset to 0 on Home
   and on any named-view snap.
3. **Widget `viewport/ViewCube.tsx`** — a curved roll-ring around the cube for free roll + ↺/↻ buttons (±90°,
   fine ±5° with a modifier). Apply the roll to `camera.up` **after** OrbitControls updates each frame
   (orbit/zoom unchanged).

**Files:** `viewport/cameraState.ts`, `viewport/ViewCube.tsx`, `store/useStore.ts`, `i18n/strings.ts`,
`styles.css`, `tests/`.

**Tests:** `view_roll.spec` (pure `rollUpVector`: 0 → element up; 90° → perpendicular; round-trip). RTL: the
roll buttons exist and update `rollRad`; Home resets it.

**DoD:** roll tilts the scene in-plane; orbit/zoom unaffected; Home + named views re-level; roll reachable by
keyboard and absent from every exported `.rcfg`. + template.
